## 原文摘要翻译

本文提出 `Infinigen Indoors`，一个基于 `Blender`、用于生成照片级真实室内场景的程序化生成器。它建立在原本聚焦自然场景的 `Infinigen` 之上，通过引入家具、建筑构件、家用电器及日常物品等多样化的程序化室内资产，将覆盖范围扩展到室内环境。论文还提出一种基于约束的布局系统，其中包含用于表达多样场景构成约束的领域专用语言，以及生成最大程度满足约束的场景布局求解器。

作者提供导出工具，使生成的三维对象和场景能够直接用于 `Omniverse`、虚幻引擎等实时仿真器中的具身智能体训练。系统以 `BSD` 许可证开源。

## 创新点

1. **把室内资产本体也程序化。** 系统不是在有限家具库中重排对象，而是用紧凑的概率程序生成形状、材质与细节，因此对象级和场景级随机化可以同时发生。
2. **引入声明式约束语言。** 用户用约束计算图描述“想要什么”，如数量、邻近、对称、可达性和物理稳定性；求解器负责“如何做到”，把场景意图与布局实现解耦。
3. **用分层模拟退火搜索组合布局。** 求解从户型、大型家具推进到中小物件，并根据场景关系限制对象自由度；缓存、平面哈希和占位几何降低反复碰撞与距离计算成本。
4. **补齐实时仿真导出链。** 系统通过纹理烘焙、格式转换、碰撞体和机器人描述文件生成，把程序材质转成可供虚幻引擎和 `Isaac Sim` 消费的资产。
5. **用“数据是否有用”而非只用“图是否好看”验证。** 阴影去除、遮挡边界、求解器消融和人类感知研究共同覆盖跨域泛化、布局质量与运行成本。

## 一句话总结

这篇论文真正的贡献不是又做了一个室内渲染器，而是把“程序化资产 + 可组合场景约束 + 启发式求解 + 仿真导出”组装成一个可编程的室内世界编译器；但标题中的“照片级真实”主要由视觉结果和人类偏好支撑，并不等价于物理或具身交互真实性已经得到验证。

## 研究问题

室内合成数据长期存在三重矛盾：扫描数据真实但规模有限；艺术家制作场景可控但昂贵；使用静态资产库的程序化布局能够扩展场景数，却无法在对象几何和材质层面产生真正无穷变化。数据驱动布局模型又把规则隐式封装在训练分布中，难以针对某个机器人任务显式规定“通道不能被堵”“器具前要留操作空间”等条件。

`Infinigen Indoors` 将问题重新表述为：能否让资产和场景都由程序生成，并把室内常识写成可组合的声明式目标，再由通用求解器搜索满足这些目标的三维场景？这不是全新的程序化生成问题，而是对原始 `Infinigen` 的应用域扩展，同时新增了人工环境特有的规则控制层。

## 数据与任务定义

### 资产与场景覆盖

系统提供 `79` 个随机化对象生成器：家电 `10` 个、门窗楼梯 `14` 个、家具 `17` 个、装饰 `15` 个、小物件 `19` 个；相应可控参数合计超过 `700` 个。另有 `30` 个材质生成器和 `120` 个材质参数，覆盖木材、陶瓷、织物、金属等类别，作者称其覆盖 `OpenSurfaces` 材质类别的 `78%`，高于原始 `Infinigen` 的 `21%`。代码约 `4` 万行，其中 `2.5` 万行用于对象或材质生成。

### 验证任务

- **求解器性能：** `20` 个随机场景，每个运行 `5000` 个求解步骤，比较缓存、哈希、移动筛选、占位网格与离散移动等组件。
- **阴影去除：** 生成 `2000` 对有阴影/无阴影图像；比较只用真实 `ISTD` 训练的 `R` 与加入合成数据的 `R+S`，并在 `SRD` 上考察跨域泛化。
- **遮挡边界：** 生成 `1464` 张带真值图像，分别用 `Infinigen Indoors`、自然版 `Infinigen` 和 `Hypersim` 训练三个从零开始的 `U-Net`，在艺术家制作的建筑可视化场景上测试。
- **人类感知：** 在 `Amazon Mechanical Turk` 上做成对比较，分别询问整体真实感、仅布局真实感以及明显错误频率。

## 方法主线

### 机制流程

1. **输入与资产实例化：** 输入是随机种子、房间需求或用户给定的部分户型条件；操作是概率程序在 `Blender` 中采样对象几何、低层噪声和程序材质；输出是送往布局阶段的可调参数候选资产。
2. **约束图编译：** 输入是用户通过 Python 接口组合的语义筛选、场景图关系、几何运算和算术聚合；操作是将它们编译为可求值计算图；输出是送往求解器的硬约束与软评分项。示例住宅约束图有 `1058` 个节点、`11` 个硬约束和 `25` 个软评分项。
3. **分层搜索：** 输入是候选资产、房间邻接图和约束计算图；操作是先求户型，再按大型、中型、小型对象逐层提出增删、重采样、换关系平面、平移或旋转，并依据损失变化与温度更新状态；输出是进入场景实现阶段的布局状态。
4. **场景实现与导出：** 输入是求解后的布局；操作是实例化对象、材质、光照和相机，或进一步烘焙材质并生成碰撞/关节描述；输出是训练图像与稠密真值，或供实时仿真器消费的标准三维资产。

### 约束语言：把室内常识变成可计算目标

每条约束本质上是计算图。叶节点来自场景对象、参数或常数，中间节点包括对象集合筛选、最小距离、角度对齐、旋转/镜像对称、二维空闲空间、可达性、面积和体积等几何算子，顶层则用比较、求和与全称量化形成硬约束或连续损失。对象参数也进入图中，因此求解器不仅能移动家具，还能发现更适合可用空间的家具长宽。

约束的价值在于作用域：用户可以只对“某房间内、附着在某表面、具有某语义关系”的对象施加规则。每种房间平均约有 `15` 条特定约束，作者估计约对应 `15` 行 Python。这个成本对研究型定制尚可接受，但并不能直接推出非专家也能轻松编写复杂住宅规则。

### 布局求解：有温度的随机局部搜索

设当前场景状态为 $s$，候选移动得到 $s'$，约束图返回损失 $l(s)$ 与 $l(s')$。论文使用的接受概率可写为：

$$
p(s'\mid s)=\min\left(\exp\left(\frac{l(s)-l(s')}{\tau}\right),1\right),
$$

其中温度 $\tau$ 从 `0.25` 指数下降到 `0.001`。工程上，这意味着更优状态总被接受；早期仍可能接受较差移动以跳出局部最优，后期逐渐收敛。

搜索空间通过两种结构化先验被压缩。第一，移动概率随阶段变化：空场景更偏向增删对象和重设关系，拥挤后更偏向连续平移/旋转。第二，场景图关系直接限定自由度，例如靠墙书架只能沿墙—地交线移动。户型部分则从概率上下文无关文法或用户输入得到房间邻接图，用 `Mondrian Process` 初始化分区，再以房间面积、纵横比、凸性、通道宽度、外墙长度和楼梯占用等目标优化。

### 导出链路与具身接口

`Blender` 节点材质不能直接被其他引擎消费，因此作者先做整屋纹理坐标映射，再把颜色、粗糙度、金属度等烘焙为标准纹理。在 `RTX 4090` 上，虚幻引擎场景达到每秒 `60` 帧，启用物理的 `Isaac Sim` 达到每秒 `50` 帧。这证明格式和实时性链路可运行，但还没有验证碰撞、关节或传感器模型对具身策略训练足够准确。

## 关键结果

### 求解器消融：速度、代理分数与视觉质量并不一致

完整系统运行 `2280.68 s`，未优化版本为 `6308.92 s`，接近 `3×` 加速；去除 `BVH` 缓存增至 `4740.48 s`，去除平面哈希增至 `3522.86 s`，说明碰撞距离复用与候选平面访问是主要瓶颈。若让完整系统运行到 `100 min`，平均评分从未优化的 `89.43` 升至 `114.72`，提高约 `28%`。

### 合成数据的跨域价值

阴影去除中，加入合成数据使 `ISTD` 同域全图 `PSNR` 从 `31.96` 略降到 `31.72`，但 `SRD` 跨域全图 `PSNR` 从 `22.83` 提升到 `24.56`，`RMSE` 从 `10.84` 降到 `9.54`。更合理的结论是合成数据增加了分布覆盖、改善跨域泛化，而不是无条件提高所有测试集表现。

### 人类感知

成对比较中，`Infinigen Indoors` 被判断为整体更真实与布局更真实的比例分别为 `79.5%` 和 `76.0%`，明显高于四个对比系统；明显错误频率为 `0.175`，低于 `ProcTHOR`、`ATISS`、`SceneFormer`，但高于 `FastSynth` 的 `0.093`。因此“所有维度都最好”并不准确：它在偏好真实感上优势大，却不是错误频率最低的系统。

## 深度分析

### 真正贡献：从场景生成器到可编程世界编译器

原始 `Infinigen` 的核心是“资产由程序定义”；本作更进一步，把室内语义规律也做成程序。约束语言相当于前端，约束计算图是中间表示，模拟退火求解器是后端，最终把高层需求编译为具体场景状态。这个结构比某一类家具生成器更有长期价值，因为资产库可以持续扩展，求解后端也可被学习型提议器替换，而用户任务仍通过相同约束层接入。

### 为什么结果成立

资产参数与低层噪声解决对象外观多样性；房间语义筛选和几何约束解决布局规则；分层搜索与自由度约束控制组合爆炸；缓存与占位网格降低每次候选评估成本。这条机制链与实验模式一致：域匹配的室内资产帮助遮挡和阴影任务，缓存/哈希消融直接拉长运行时间，对称与碰撞项的定性消融则直接破坏布局观感。

### 哪些地方容易被误读

第一，`79` 个生成器不等于覆盖所有长尾室内物体；程序化变化通常围绕作者预设拓扑与参数族展开。第二，人类偏好的“真实”混合了布局、材质、光照和渲染器质量；即使单独询问布局，受试者也难完全忽略外观。第三，下游改进证明的是这两项协议中的数据价值，不是“合成数据普遍优于真实数据”。第四，实时引擎中达到 `50–60 FPS` 只说明渲染/物理管线能够运行，不能替代机器人任务中的动力学与交互验证。

## 局限

1. **规则编写仍依赖专家。** 平均每个房间约 `15` 行约束看似不多，但全屋规则、冲突处理和任务特定安全条件需要持续维护；论文没有用户研究或调试成本测量。
2. **求解器没有扩展性保证。** 模拟退火是随机局部搜索，不保证满足全部软目标或找到全局最优；缺少房间数、对象数、约束节点数对应的成功率和时间曲线。
3. **代理目标存在错位。** 去除离散移动能提高数值评分却损害视觉结果，说明评分图仍不能完整表达感知合理性。
4. **视觉评测仍偏合成域。** 遮挡边界测试集是艺术家场景；阴影实验加入合成数据后同域 `ISTD` 略降，跨域收益的边界需要更多真实数据集确认。
5. **具身价值尚未闭环。** 论文提供导出工具，却没有导航、操作、具身问答或 sim-to-real 任务的训练收益；物理、关节和传感器真实性仍是未验证变量。
6. **复现实验有一处值得警惕。** 作者无法复现 `ShadowFormer` 代码库的预训练结果，因而比较只保证在其重新训练的相同实现内公平，不能直接对齐原论文绝对水平。

## 我的笔记

- **可复用结构：** 把语言或任务需求编译为约束计算图，再让通用搜索器执行，是连接大语言模型与三维世界生成的自然接口；大语言模型可以负责写约束，求解轨迹则提供可检查反馈。
- **值得质疑：** 软评分是否能被人类偏好或下游任务自动校准？目前它主要来自人工工程经验。
- **建议复现实验：** 固定资产与渲染，只改变约束项、移动提议和求解预算，报告约束满足率、冲突率、感知偏好与下游任务收益，隔离“布局机制”本身的作用。
- **值得比较：** 原始 `Infinigen` 用于理解资产生成底座；后续可与语言驱动场景代码生成、学习型布局模型，以及能够从执行错误修复约束程序的三维智能体方法对照。
- **后续问题：** 让语言模型生成约束后，如何将“不满足约束”的局部证据转成最小程序修补，而不是每次重新生成整段场景代码？
