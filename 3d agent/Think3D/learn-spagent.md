# 学懂 Think3D / SPAgent：让 VLM "在 3D 空间里思考"

> 论文：**Think3D: Thinking with Space for Spatial Reasoning**（arXiv:2601.13029v3）
> 作者：Zaibin Zhang, Yuhan Wu, Lianjie Jia 等（大连理工大学 / UCSD / Oxford）
> 代码：就是你现在所在的这个仓库（SPAgent 是框架名，Think3D 是论文提出的方法名）

这份笔记按"是什么 → 为什么 → 怎么做 → 效果如何 → 代码在哪"的顺序讲解，最后附自测题。

---

## 1. 一句话总结

**给视觉语言模型（VLM）配一套"3D 操作工具"：先把多视角图片重建成 3D 点云，然后让模型像人转动脑中的 3D 模型一样，反复"换个角度看一眼"，直到看懂空间关系为止。** 不训练也能让 GPT-4.1、Gemini-2.5-Pro 大幅涨点；对小模型（Qwen3-VL-4B）再加一层强化学习（Think3D-RL），教会它"该往哪儿看"。

---

## 2. 背景：VLM 为什么不擅长空间推理？

先建立问题直觉。想象你看到 4 张从不同位置拍摄的房间照片，问题是："如果我站在第 4 张图的位置，我背后是什么？"

人类怎么解？我们会在脑中把 4 张照片**拼成一个 3D 场景**，然后在脑中"转身"看一眼。认知科学里这叫心理旋转（mental rotation）。

而目前的 VLM 本质上是**被动的 2D 分析器**：它把每张图独立编码成 token，缺乏一个跨视角一致的 3D 表征。所以在 MMMU 这类综合评测上接近人类水平的模型，在多视角理解、路径规划这类任务上依然远落后于人类。

论文梳理了两条已有的补救路线，以及各自的短板：

| 路线 | 做法 | 短板 |
|------|------|------|
| 内化空间知识 | 用大规模空间数据集做训练（SpatialVLM、VLM-3R 等） | 算力开销巨大，还可能损伤通用推理能力 |
| Think with Image | 让模型调用 zoom / crop / 深度估计等 2D 工具（DeepEyes 等） | 只能提供"2.5D"的浅层线索（相对深度、计数），无法跨视角做真正的 3D 几何推理 |

于是论文的核心问题是：**VLM 能不能像人一样"用 3D 空间来思考"（Think with 3D Space）？**

时机上的推手：Pi3、VGGT、DUSt3R 这类前馈式 3D 重建模型成熟了——不需要标定相机，喂几张图就能直接吐出点云 + 相机位姿。这给了 VLM 一个可以"动手操作"的几何底座。

---

## 3. 核心思想：从"看图"变成"探索场景"

Think3D 把空间推理改造成一个**多轮交互循环**：

```
观察 (observe) → 操作 (manipulate) → 反思 (reflect) → …循环…→ 回答
```

具体流程（对应论文图 2）：

1. 输入多视角图片 {I_t} 和问题 q；
2. VLM **自主决定**是否调用 3D 重建工具（Pi3），得到点云 + 每个相机的位姿；
3. 每一轮，VLM 输出一个"操作指令"：选哪个相机作锚点、往哪个方向转多少度、要全局视角还是第一人称视角；
4. 工具渲染出新视角图片，追加进对话历史；
5. 模型看完新图，决定继续探索还是给出最终答案（可提前 STOP）。

默认最多 K=3 轮渲染，整个问题最多做 1 次重建。

**为什么这不只是"多问几轮"？** 论文专门做了对照（5.6 节）：用 Self-Refine 让 GPT-4.1 同样跑 3 轮纯文字自我批评，token 花得更多（7.7k vs Think3D 的 6.7k），提升却微乎其微。涨点来自**真实的新几何证据**，不是来自多轮对话本身。这是理解这篇论文的关键一点。

## 4. 方法细节：三大组件

### 4.1 3D 操作工具箱（3D Manipulation Toolkit）

工具箱提供三种能力，读公式前先记住直觉：**重建给你一个"数字沙盘"，变换让你转动沙盘或转动脑袋，渲染把你看到的画面拍成照片**。

**(1) 3D 重建。** 用 Pi3 从多视角图片估计出：

- 每个相机 `C_t = (K_t, R_t, t_t)`——内参矩阵、旋转矩阵、相机中心（世界坐标）；
- 融合各视角的深度和置信度，得到干净的彩色点云 `X = {(x_n, c_n)}`（3D 坐标 + RGB 颜色）。

**(2) 3D 变换。** 每一步，agent 预测一个动作四元组：

```
a_k = (i, m, Δα, Δβ)
      │  │   └─┴── 方位角(左右转)、俯仰角(上下转)
      │  └── 模式: global(全局) 或 ego(第一人称)
      └── 锚点相机编号 i ∈ {1..T}（对应第 i 张输入图）
```

两种模式的几何含义值得细品：

- **global 模式（转沙盘）**：相机不动，把整个点云绕场景中心 c（点云质心）旋转——公式 (3)：`x' = s·ΔR(Δα,Δβ)·(x − c) + c`。效果像把整个场景托在手上转，用来看**整体布局**（比如俯视图看物体相对位置）。
- **ego 模式（转脑袋）**：点云不动，站在第 i 号相机的位置原地转头——公式 (4)：`C_new = (K_i, ΔR·R_i, t_i)`，注意相机中心 t_i 不变，只改朝向。用来回答"站在这个位置能看到什么"这类**第一人称**问题。

**(3) 新视角渲染。** 用轻量点云渲染器出图。ego 模式下会先把点云裁剪到虚拟相机前方一个宽视场锥内，模拟真实的第一人称视野。渲染图里相机用锥形标记（frustum）画出来并编号，cam1 对应第 1 张输入图——这让模型能把"2D 图片里看到的内容"和"3D 空间里的相机位置"对上号。

**为什么必须用相机位姿做锚点？** 这是论文的一个关键设计（也是消融里最重要的一行）。如果没有一致的参考系，"向左转 45°"是相对什么的？模型的空间操作会变得歧义丛生。用估计出的相机位姿做锚，约定 (azimuth=0°, elevation=0°) 恰好就是输入图的视角，所有旋转都定义在这个坐标系里，模型的每一步操作才有确定语义。

### 4.2 空间推理 Agent

形式化很简洁：第 k 轮时，VLM 是一个多模态策略

```
o_k = π_θ(q, {I_t}, H_{k−1})
```

输出 o_k 解析为"文字推理 + 可选的工具调用"。渲染出的新图 Î_k 连同动作 a_k 一起追加进历史：`H_k = H_{k−1} ‖ [(Î_k, a_k)]`。模型于是维护着一条**显式的 3D 思维链**——每一步的"想法"都对应一次真实的几何观察。

工程上靠三段式 prompt 支撑（附录 A，正是本仓库 `spagent/core/prompts.py` 里的内容）：

- **系统 prompt**：定义角色、工具调用格式（`<tool_call>` JSON）、输出格式（`<think>`/`<answer>`）；
- **工具 prompt**：讲清参数语义，并明确告诫"输入图已经是 (0°,0°) 视角，别再要一遍"，同时推荐候选角度（左右 ±45°/±90°、俯视 (0°,60°)、背面 180°、斜角 (45°,30°)…）；
- **续轮 prompt**：每轮开头提醒任务目标、剩余轮数、已看过的角度，避免模型原地打转。

一个有趣的实操提示直接写进了 prompt："涉及朝向或相对位置的问题，推荐俯视图（top view）"——这是从强模型行为里总结出来的经验。

### 4.3 Think3D-RL：教小模型"会看"

论文的一个核心观察：**探索质量和模型基础推理能力强相关**。GPT-4.1、Gemini-2.5-Pro 会主动选多样且有意义的视角；小模型（Qwen3-VL-4B）则容易选冗余甚至误导性的视角——工具白给了，不会用。直接套 Think3D，4B 模型只涨 +0.7%。

解决方案是强化学习，设计上有几个巧思：

**轨迹与奖励。** 一条轨迹 τ = 多轮 (状态, 输出) + 最终答案 ŷ。奖励**只在轨迹末尾**给：

```
R(τ) = R_ans(ŷ) + R_fmt(ŷ)
        │            └── 小的格式奖励（输出格式正确）
        └── 答案是否匹配选择题正确选项
```

没有任何"你该怎么转视角"的中间监督——**不需要标注操作轨迹**。答对了，这条轨迹上所有的视角决策一起被强化；答错了一起被抑制。模型自己摸索出"什么时候探索、往哪儿看"。

**训练细节。**
- 算法：GRPO（组相对策略优化），每步 8 条 rollout 估计优势；
- 关键 mask：渲染图的 observation token 上**停掉梯度**，只优化模型自己生成的动作和答案 token（跟 DeepEyes 一致）——你不能因为"看到的画面"惩罚模型，只能针对它的"决策"；
- 效率：训练前**预先为所有场景重建好点云**，训练时只做渲染，不跑 Pi3 推理，否则每条 rollout 都要在线重建，训练慢到不可行；
- RL 版 prompt 把动作空间收窄到 8 个候选角度，且按"首轮 / 中间轮 / 最后一轮"用不同的阶段化 prompt（小模型指令跟随弱，最后一轮直接禁止再调工具，强制作答）；
- 数据非常省：只用 MindCube 里随机抽的 **977 个样本**，训 1 个 epoch（8×H200，lr 1e-6，完整超参见论文附录表 5）。

**RL 训练动态很有戏剧性**（5.3 节）：前 ~50 步，模型发现"少调工具、快点答题"能薅到格式奖励，于是轮数下降——但准确率也跟着掉（视角少了）。之后模型逐渐学会"多花一两轮换来正确答案更划算"，工具调用回升，准确率稳步上涨。这本质上是模型在探索成本和信息收益之间找平衡。

## 5. 实验结果：数字背后的故事

三个基准：**BLINK Multi-view**（跨视角推断相机运动）、**MindCube**（rotation/among/around 三类相机运动，各采样 40 题）、**VSI-Bench-tiny**（第一人称视频空间智能：路径规划、相对方向、出现顺序、相对距离，每视频采 7 帧）。

### 关键数字（准确率 %）

**BLINK + MindCube（表 2）：**

| 模型 | 平均 | 加 Think3D | 提升 |
|------|------|-----------|------|
| GPT-4.1 | 49.62 | **61.19** | +11.57（BLINK 单项 +27.09！） |
| Gemini-2.5-Pro | 59.34 | **63.34** | +4.00 |
| Qwen3-VL-4B（原始） | 35.92 | 36.53 | 仅 +0.61 |
| Qwen3-VL-4B + Think3D-RL | 34.65 | **43.97** | **+9.32** |

**VSI-Bench-tiny（表 1）：** GPT-4.1 +2.96，Gemini-2.5-Pro +6.45；Qwen3-VL-4B 从 +0.80 变成 RL 后的 **+12.05**，平均 45.41 分——一个 4B 模型追平甚至超过了不带工具的 GPT-4.1（48.18 vs 45.41 已很接近）和一票专门的空间模型。

三个值得记住的解读：

1. **工具的收益是"能力门槛型"的**：强模型即插即用大涨，弱模型几乎不涨——瓶颈不在工具，在"会不会用"；
2. **RL 补的正是这块短板**：对照组 Qwen3-VL-4B 用普通 GRPO（无工具）训练只有 33.30 分，说明涨点来自"学会探索"，不是来自 RL 微调本身；
3. **RL 学到的是策略，不是运气**（附录 D 的漂亮对照）：随机选角度 36.68 分、固定启发式角度 38.69 分、**RL 训练过的模型 + 随机角度只有 37.56 分**、RL 模型 + 自己选角度 **47.11 分**。同一个 backbone，换掉它自己的视角选择，收益就没了——涨点确实来自学到的空间探索策略。

### 消融：每个组件都在挣钱（表 3，GPT-4.1 on BLINK）

| 3D重建 | 相机锚点 | 相机选择 | ego视角 | BLINK |
|:--:|:--:|:--:|:--:|:--:|
| | | | | 36.82 |
| ✓ | | | | 41.17 |
| ✓ | ✓ | | | 55.46 |
| ✓ | ✓ | ✓ | | 61.65 |
| ✓ | ✓ | ✓ | ✓ | **63.91** |

最大的一跳来自**相机锚点**（41→55）：光把点云丢给模型没多大用（MindCube 上甚至掉分），必须给它一个一致的参考系去主动操作。这验证了第 4.1 节末尾那个设计动机。

### 其他有意思的发现

- **探索模式是任务相关的**（图 4a、图 16）：路径规划/出现顺序类任务，GPT-4.1 几乎全用俯视全局图；MindCube/物体朝向类任务则大量用旋转视角和 ego 视角。模型自发形成了"任务→视角"的映射。
- **RL 后的小模型行为趋近大模型**（图 4b）：Qwen3-VL-4B 训后视角分布向 GPT-4.1/Gemini 靠拢（更多俯视图）——没人教它，纯靠答案奖励涌现。
- **探索轮数**（图 6）：没 RL 的模型，多给轮数不涨分；RL 后的模型轮数越多分越高——学会了从追加观察中持续提取信息。
- **对重建器不敏感**（表 4）：把 Pi3 换成 VGGT，BLINK 59.65 / MindCube 59.59，仍远高于无工具基线（36.82 / 53.89）。框架是重建器无关的，未来更强的重建模型可以直接换入受益。

## 7. 批判性视角：边界与局限

学一篇论文也要知道它没解决什么：

1. **依赖重建质量**。点云来自前馈重建模型，纹理弱、视角稀疏、动态场景下重建会退化；渲染是点云渲染，有空洞和噪声（论文用"重建器无关"消融部分回应了鲁棒性，但没测重建失败的场景）。
2. **动作空间较窄**。只有"选相机 + 转角度 + 全局/ego"，没有平移（walk）、缩放探索有限（global 的 s 默认为 1）、不能操作单个物体。"路径规划"这类任务或许需要在场景里"走动"。
3. **评测规模偏小**。MindCube 只采样 120 题、VSI-Bench 用 tiny split（论文每个设置跑 3 次取平均来缓解方差）。
4. **RL 只在选择题奖励上验证**。R_ans 是选项匹配，开放式空间问答如何给奖励仍是开放问题。
5. **推理成本**。每题多一次重建（RTX 3090 上跑 Pi3）+ 最多 3 次渲染 + 更长的多模态上下文（约 6.7k token）——比裸模型贵约 5 倍 token，虽然比 Self-Refine 便宜且有效得多。

能不看上文回答这些问题，就算真学会了：

1. "think with image" 和 "think with 3D space" 的本质区别是什么？为什么前者被称为 "2.5D" 操作？
2. global 模式和 ego 模式在几何上分别变换什么、固定什么？各适合回答哪类问题？
3. 为什么"相机锚点"是消融中收益最大的组件？没有它会出什么问题？
4. Think3D-RL 的奖励里没有任何视角选择的监督，模型是怎么学会"往哪儿看"的？训练曲线前 50 步为什么先变差？
5. 论文用哪两个对照实验分别排除了"涨点来自多轮对话"和"涨点来自 RL 微调本身（而非探索策略）"这两种质疑？
6. 为什么 RL 训练时要预先重建点云、并对 observation token 做梯度 mask？

<details>
<summary>参考答案要点（点开核对）</summary>

1. 前者在 2D 图像平面上操作（裁剪/缩放/深度图），只能得到相对深度、计数等浅层线索，无法建立跨视角一致的几何表征；后者在重建出的 3D 点云上操作，能渲染任意新视角，支持真正的跨视角几何推理。
2. global：相机固定，点云绕场景质心旋转（公式 3）——看整体布局，适合相对位置/俯视类问题；ego：点云固定，虚拟相机在锚点相机位置原地转头（公式 4，t_i 不变）——适合"站在某处能看到什么"的第一人称问题。
3. 它提供一致的参考系：所有旋转都相对某个输入相机定义，(0°,0°) 即输入图视角。没有锚点时"向左转"语义歧义，消融显示裸 3D 输入甚至会掉分（BLINK 41.17 vs 加锚点 55.46）。
4. 轨迹级奖励（答案对错）把功劳/责任分摊到整条轨迹的所有视角决策上（GRPO 组内相对优势），好的探索序列被整体强化。前 50 步模型先学会"少调工具快答题"薅格式奖励，导致视角证据不足、准确率下降，之后才学会用额外轮数换正确率。
5. Self-Refine 对照（同样 3 轮、更多 token、几乎不涨）排除"多轮对话"解释；Qwen3-VL-4B-GRPO（无工具 RL，33.30 分）和 RL-random（RL 模型+随机角度，37.56 vs 47.11）排除"RL 微调本身"解释。
6. 在线重建每条 rollout 都要跑 Pi3，训练慢到不可行，预重建后训练时只需渲染；observation token 是环境给的（渲染图），不是模型的决策，对其算策略梯度没有意义且会引入噪声——只应优化模型生成的动作与答案 token。

</details>
