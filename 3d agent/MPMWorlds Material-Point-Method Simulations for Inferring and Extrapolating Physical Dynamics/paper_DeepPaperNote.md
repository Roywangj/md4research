# MPMWorlds: Material-Point-Method Simulations for Inferring and Extrapolating Physical Dynamics

## 原文摘要翻译

为了研究模型能否从视频中推断物理动力学，并把这种动力学向未来时间外推，作者构建了一个二维物质点法物理仿真数据集。该数据集覆盖可变形物体、流体、运动物体和发射器等丰富物理现象。作者在这个数据集上研究代码生成方法和视频扩散方法，并通过改变可获得的物理相关旁路信息，识别两类方法各自的优势与弱点。代码生成模型不仅展示了自动合成物质点法仿真的可行性，也揭示了这种方法难以从视觉输入中推断物理参数；但相对于视频扩散，它能生成物理上和时间上更稳定的未来外推。视频扩散模型则更擅长从视觉输入中识别几何属性，但生成的外推往往在物理上不合理。项目页见 https://zzigak.github.io/mpmworlds/。

## 创新点

1. 把物理推理评测从“看起来合理的视频”推进到“可执行仿真、结构化状态和未来外推”的三元组。每个样本都有程序、配置和视频，因此能追问模型到底缺几何、材料还是动力学。
2. 用 MPMWorlds 覆盖多材料复杂物理。数据不只包含刚体碰撞，还包含液体、雪、沙、弹性/塑性形变、运动碰撞体和连续发射器，更接近 3D/4D 世界模型真正会遇到的物理难点。
3. 同时比较两条路线：VLM 生成 Taichi MPM 程序，VDM 直接续写像素视频。这个对照很干净，因为两者面对相同视频前缀和相同可选场景信息。
4. 四种输入条件把错误拆得很细。仅帧、完整配置、去材料、去位置分别诊断视觉推断、材料推断和空间状态估计。
5. 指标不只看像素误差。论文加入物体坍缩、运动活跃度、颜色分布和时间异常等长时序指标，能捕捉“画面还像，但物理已经坏掉”的失败。
6. 用 prefix-quality threshold gate 做了一个很小但有启发的混合原型。它说明代码路线和视频路线不是简单替代关系，而是可以按前缀重建质量路由。

## 一句话总结

MPMWorlds 的价值不在于提出一个更强生成模型，而在于把“视觉几何是否对、物性是否推得出、动力学能否长时间稳定”拆成可诊断的物理世界模型基准；它清楚地显示，当前 VLM 更像稳定但眼神不够准的物理程序员，VDM 更像画面感很好但容易忘记物理守恒的视频画师。

## 研究问题

### 它到底想测什么

论文研究的问题是：给定一个物理场景的短视频前缀，以及可选的旁路场景信息，模型能否恢复一个等价的前向物理过程，并把它外推到未来视频。这里的物理过程可以是显式程序，也可以是视频模型内部的隐式状态。

这个定义比常见视频预测更严格。普通视频预测只要未来帧像真一点即可；这里还要求长期保留物体、材料、速度和交互结构。对 3D agent 来说，这正好对应一个更底层的问题：如果智能体要在世界里规划，它需要的不只是下一帧图像，而是能持续外推的物理世界模型。

### 为什么它属于 3D agent 图谱

这篇论文本身不是具身智能体方法，也不是三维空间问答模型。它应该放在 3D agent 目录里的“物理世界模型 / 仿真基准 / 长时序推理”分支。原因是它回答了一个很实在的问题：当我们让 agent 依赖视频世界模型或代码世界模型做规划时，到底哪类模型更容易保持几何、材料和动力学一致？

和 Code2Worlds 的关系尤其近。Code2Worlds 把语言变成 Blender 仿真代码，目标是开放四维世界生成；MPMWorlds 则把可执行仿真作为受控基准，用来测代码生成路线和视频生成路线的物理能力边界。前者偏系统构建，后者偏诊断评测。

## 数据与任务定义

### 数据三元组

每个 MPMWorlds 样本包含三件东西：可执行 Taichi MPM 仿真代码、结构化 YAML 场景配置，以及仿真渲染得到的视频。配置描述对象类型、几何、材料模型、初始状态、外观、运动碰撞体和发射器等属性；代码实现对应的物理过程；视频提供可见观测。

这个三元组很关键。它让研究者可以分别观察三个层面的失败：视觉前缀是否足以恢复场景状态，结构化配置是否能被模型利用，生成的程序或视频是否能在未来保持物理一致。

### 数据生成与规模

数据从 `35` 个手写种子仿真起步。作者用 ChatGPT o3 和 Gemini 2.5 Pro 按 Self-Instruct 风格扩展，生成新的仿真程序和场景配置，并通过运行检查、数值稳定性检查、配置一致性检查和人工复核筛掉坏样本，得到约 `1k` 个父级仿真。随后再让模型修改已有场景，加入或删除对象、改变材料和几何、调整交互，得到约 `9k` 个子级仿真。

最终数据集包含 `95,805` 个渲染仿真和 `9,204` 个 Scene Templates。场景对象数中位数是 `3`，均值是 `2.9`。材料覆盖液体、弹性材料、雪、黏塑性材料和沙；`22.5%` 的场景含至少两种材料，`5.3%` 的场景含三种或更多材料。对象类型包括动态可变形体、静态碰撞体、运动碰撞体和发射器。

视频原始渲染为 `512×512`、`30 FPS`、`10` 秒。训练和推理时缩放到 `256×256`、`15 FPS`。这一步降低成本，但也意味着评测重点不是高分辨率视觉质量，而是中低分辨率下的物理结构和时序稳定性。

### 输入条件

| 输入条件 | 给模型的信息 | 实际诊断问题 |
| --- | --- | --- |
| Frames Only | 约 `2.5` 秒视频前缀 | 只凭视觉能否恢复全部状态 |
| Full Configuration | 视频前缀加完整 YAML 场景配置 | 在几乎有特权信息时能否正确外推 |
| No Materials | 去掉材料身份和材料参数的配置 | 模型能否从视觉推断物性 |
| No Positions | 去掉显式位置的配置 | 模型能否从视觉推断几何布局和初始状态 |

这四组条件设计得很漂亮。它不只是问“谁分数高”，而是在问 VLM 和 VDM 分别依赖哪类信息。尤其是 No Materials 和 No Positions，让材料推断和几何状态估计变成可观察的缺口。

### 评价指标

| 指标 | 越大越好/越小越好 | 测量内容 |
| --- | --- | --- |
| mIoU | 越大越好 | 预测视频和真值视频的前景掩膜重叠，主要反映粗几何占据 |
| Object Collapse Score | 越小越好 | 预测早期出现的物体或材料区域在后续帧是否消失 |
| W-MAE | 越小越好 | 预测运动活跃度和真值运动活跃度是否一致 |
| CTV | 越小越好 | 前景颜色分布差异，近似反映外观和材料组成 |
| Temporal Anomaly Rate | 越小越好 | 是否发生超过真值的局部突变、闪烁或异常跳变 |

论文还报告 SEMD 和 MSE，但不把它们作为主要指标，因为像素误差和地动距离不一定能反映长时序物理一致性。这一点对视频世界模型评测很有启发：一个视频可以像素上接近，却在物体持久性、材料体积和运动因果上已经崩掉。

## 方法主线

### 机制流程

![Figure 1](3d%20agent/MPMWorlds%20Material-Point-Method%20Simulations%20for%20Inferring%20and%20Extrapolating%20Physical%20Dynamics/images/page_002_fig_figure_1.png)
*Figure 1：MPMWorlds 数据集总览。样本覆盖多材料交互、沙、运动碰撞体、发射器、网格仿真和多对象场景；每个样本包含 MPM 仿真器、场景配置和仿真视频。*

![Figure 2](3d%20agent/MPMWorlds%20Material-Point-Method%20Simulations%20for%20Inferring%20and%20Extrapolating%20Physical%20Dynamics/images/page_004_fig_figure_2.png)
*Figure 2：两条重建与外推管线。VLM 从观测和可选场景信息生成可执行程序，再运行程序得到完整视频；VDM 在像素空间直接续写未来帧。*

1. 输入是一个真实仿真程序和它的结构化场景配置。操作是运行 MPM 仿真并渲染视频。输出是程序、配置和视频三元组。
2. 输入是视频前缀和可选配置。操作是遮掉未来帧，只保留可观测信息。输出是四种诊断条件下的模型输入。
3. 输入进入 VLM 路线后，模型生成可执行 MPM 程序。操作是运行该程序并比较可见前缀。输出是被选中的程序及其未来外推。
4. 输入进入 VDM 路线后，模型把视频前缀作为条件。操作是在像素空间直接续写未来帧。输出是没有显式物理中间层的视频外推。

### VLM：把物理动态写成可执行程序

VLM 使用 Qwen2.5-VL-7B-Instruct。输入包括视频前缀采样帧、可选场景信息和轻量程序 scaffold。scaffold 只固定导入、函数签名和非语义代码结构，真正的仿真逻辑、对象初始化、材料参数和更新规则由模型生成。

这一路线的优势是输出会进入 MPM 仿真器。只要代码逻辑大体正确，后续帧就会受到物理积分和状态更新约束，因此更容易保持长时序稳定。短板也很明显：模型必须把视觉前缀转成准确的几何、材料和参数。如果位置或材料推错，程序越稳定，错误也越稳定。

### VDM：把物理动态压进像素续写

VDM 使用 `14B` LongCat video continuation model。它不构建显式物理表示，而是直接基于视频前缀和可选文本化场景信息生成未来帧。论文发现它在 mIoU 上经常更好，说明它能从像素条件里保留粗几何和前景位置。

但 VDM 的问题也很典型：像素空间续写可以短期看起来顺滑，却没有可靠的物体持久性和材料守恒。长 horizon 后，它更容易出现物体淡出、区域消失、运动漂移、局部突变或多材料合并成平均纹理。

### 训练、切分与 Best-of-N

所有实验使用一个 `10k` 样本子集，并提高基础场景的采样权重。主要测试集按父级仿真切分：一个留出的父级仿真的所有子级版本和扰动都进入测试，因此模型训练时从未见过该底层场景模板。这个切分更接近真正新场景泛化。

作者还构建了 modification validation split。它保留部分训练场景族，只把训练 base scene 的某些修改后代拿出来验证，因此难度介于记忆和完全新场景之间。

推理时，VLM 每个测试样本采样 `15` 个候选程序，用可见前缀的指标选择最好的程序。VDM 在不同随机种子下多样性较低，因此每个样本只采样 `1` 个视频，并使用 `50` 个去噪步。作者认为这让两条路线推理时间大致可比。

### Prefix-quality threshold gate

论文最后做了一个简单 gating：对每个样本，看 VLM 生成结果在可见前缀上的重建质量，如果前缀质量足够好，就信任 VLM 的未来外推；否则回退到 VDM。这个 gate 不复杂，但它抓住了一个很有用的信号：如果程序连已观察部分都重建不好，未来通常也不可信。

从世界模型角度看，这个 gate 像是一个早期混合架构雏形。未来更自然的方向是让视觉模型负责状态估计，让可执行或结构化动力学模型负责长时序外推。

## 关键结果

### 主结果：VLM 更稳，VDM 更像

*Figure 4：VLM 与 VDM 在不同输入条件和主要指标上的对比。VLM 在运动、异常和坍缩指标上更稳；VDM 在 mIoU 上更强。*

![Table 2](page_013_fig_table_2.png)
*Table 2：测试集上 VLM 与 VDM 的完整视觉指标，报告均值和标准误。该表补充 Figure 4 的主要数值。*

最核心的结论是互补而不是单边胜利。完整配置下，VLM 的 W-MAE、CTV、异常率、坍缩分数分别是 `0.254`、`0.188`、`0.371`、`0.163`，VDM 分别是 `0.298`、`0.251`、`0.862`、`0.366`。这说明在运动幅度、外观组成、时间异常和物体坍缩方面，代码生成路线更稳定。

但掩膜交并比反过来。完整配置下 VLM 的数值是 `0.512`，VDM 是 `0.611`；仅帧条件下 VLM 是 `0.316`，VDM 是 `0.578`。这说明 VDM 更擅长从像素前缀保留粗几何和前景占据。换句话说，VDM 经常“位置看着更对”，但未来物理更容易坏。

### 旁路信息到底帮了谁

Figure 4 显示，VLM 对结构化场景信息高度敏感。去掉材料或位置会明显损害性能，尤其影响 CTV 和 W-MAE。这个结果说明 VLM 并不是从视频中自然学会了完整物理状态，而是强依赖显式配置来补足视觉估计。

VDM 的变化则小很多。即便给它相同的文本化场景信息，它也不稳定地利用这些信息。论文甚至观察到，移除材料信息后 VDM 在若干材料类别上略有改善。这不是说材料不重要，而是说当前像素空间视频模型没有很好地把结构化物理参数转成未来动力学。

### 材料族差异

![Figure 5](3d%20agent/MPMWorlds%20Material-Point-Method%20Simulations%20for%20Inferring%20and%20Extrapolating%20Physical%20Dynamics/images/page_008_fig_figure_5.png)
*Figure 5：移除材料信息后的性能变化。VLM 在弹性/塑性、雪和沙上明显受损；VDM 移除材料信息后反而略有改善。*

![Figure 7](3d%20agent/MPMWorlds%20Material-Point-Method%20Simulations%20for%20Inferring%20and%20Extrapolating%20Physical%20Dynamics/images/page_009_fig_figure_7.png)
*Figure 7：按材料族归一化后的平均表现。VLM 在液体和雪上较强，在沙上明显困难；VDM 对弹性/塑性场景更吃力。*

对 VLM 来说，沙是最难的材料族。论文解释得很合理：Drucker-Prager sand 虽然属于弹塑性范畴，但它有颗粒流动、摩擦屈服和形状不保持等特性，代码实现也更复杂。液体反而相对容易，可能是因为视觉形态和指标对精细参数不那么敏感。

对 VDM 来说，弹性/塑性高动态场景更困难。很多这类场景包含反弹、快速形变或相干物体轨迹，需要精确传播速度和几何；VDM 容易出现漂移、消失和不一致运动。液体虽然视觉复杂，但只要维持大致流动外观，短期看起来反而更容易过关。

### Gate 说明两类模型确实互补

![Table 1](3d%20agent/MPMWorlds%20Material-Point-Method%20Simulations%20for%20Inferring%20and%20Extrapolating%20Physical%20Dynamics/images/page_010_fig_table_1.png)
*Table 1：VLM、VDM 与阈值门控在测试集上的首选候选对比。门控在多数稳定性指标上优于单一路线；mIoU 多数选择 VDM。*

阈值门控的收益很强。完整配置下，W-MAE 从 VLM 的 `0.254` 和 VDM 的 `0.298` 降到 `0.144`；异常率从 `0.371` 和 `0.862` 降到 `0.001`；坍缩分数从 `0.163` 和 `0.366` 降到 `0.126`。这些结果说明前缀重建质量确实能预测未来展开是否可信。

更有意思的是 mIoU 的选择比例。完整配置下，mIoU 门控只有 `23%` 样本选择 VLM；仅帧条件下是 `0%`。这和主结论完全一致：几何占据更常由 VDM 给出更好结果，而稳定动力学更常由 VLM 给出更好结果。

### 新场景比熟悉变体更难

![Table 3](3d%20agent/MPMWorlds%20Material-Point-Method%20Simulations%20for%20Inferring%20and%20Extrapolating%20Physical%20Dynamics/images/page_015_fig_table_3.png)
*Table 3：修改验证切分上的完整指标。相较完全留出测试切分，模型在熟悉场景族的变体上更容易泛化。*

修改验证切分上两类模型都会改善，因为它们见过相关场景族，只是对象布局、材料或参数发生变化。VLM 的提升更明显，尤其是运动和时间稳定性。这个结果说明，VLM 可能更容易利用熟悉的程序结构和交互模式；VDM 也受益于熟悉视觉模式，但坍缩和异常率仍然偏高。

## 深度分析

### 真正贡献是什么

这篇论文真正贡献的是一个诊断坐标系：物理世界模型不是一个单分数任务，而至少要分成几何状态估计、材料属性推断、动力学外推和长时序稳定性。MPMWorlds 用同一个底层仿真系统把这些变量控制住，让 VLM 和 VDM 的短板变得可见。

它比一般视频生成评测更“工程可用”。如果一个模型在 mIoU 上好但坍缩很差，我们知道它更像视觉续写器；如果一个模型坍缩很低但 mIoU 差，我们知道它可能有可执行动力学，但状态估计有问题。这种信息对后续搭建智能体世界模型，比单个 VBench 或 CLIP 分数更有用。

### 为什么 VLM 稳定但几何弱

![Figure 10](3d%20agent/MPMWorlds%20Material-Point-Method%20Simulations%20for%20Inferring%20and%20Extrapolating%20Physical%20Dynamics/images/page_013_fig_figure_10.png)
*Figure 10：物体持久性和材料推断失败案例。左侧 VLM 保持轨迹而 VDM 发生物体消失；右侧移除材料信息后，VLM 误判液体交互，而 VDM 更依赖像素模式。*

VLM 的稳定性来自可执行中间表示。生成程序一旦进入 MPM 引擎，未来状态由积分、材料模型和碰撞逻辑推进，而不是每帧重新“画”。这天然降低了物体突然消失和局部跳变。

但 VLM 的瓶颈是从视觉到状态。它必须估计位置、形状、材料、速度和参数，再把这些东西写进程序。去位置条件下 mIoU 明显下降，说明它很难仅从帧中恢复精确几何布局。去材料条件下材料族差异很大，说明视觉材料识别也不稳定。对智能体来说，这意味着“会写仿真代码”不等于“会看懂当前世界状态”。

### 为什么 VDM 几何强但动力学弱

![Figure 11](3d%20agent/MPMWorlds%20Material-Point-Method%20Simulations%20for%20Inferring%20and%20Extrapolating%20Physical%20Dynamics/images/page_014_fig_figure_11.png)
*Figure 11：复杂动力学和空间推理的对照失败。VDM 能保存部分几何布局，但在高能多材料交互中出现物体坍缩；VLM 在缺少位置时会幻觉障碍布局。*

VDM 的优势是直接条件化像素。它不需要把图像先离散成程序参数，因此更容易保留粗位置、轮廓和前景占据。mIoU 的优势就是这个性质的体现。

问题在于，像素续写不保证物体身份、体积、材料和速度的可积累一致性。视频可以在短期像真实世界，却在长期把弹性块画没、把刚体融进流体，或者让多材料混成静态平均外观。Figure 11 的例子很典型：VDM 的空间布局未必最差，但在高能交互和多材料组合里会出现物理坍缩。

### 长 horizon 才暴露本质问题

![Figure 13](page_016_fig_figure_13.png)
*Figure 13：Full Configuration 下的累计坍缩率。VDM 在外推早期就开始大量坍缩，最终坍缩率显著高于 VLM。*

这篇最有价值的地方是把短期视觉合理性和长期物理一致性分开。很多视频模型在前几帧可以靠纹理延续和局部运动过关，但随着 horizon 拉长，内部没有稳定状态变量的缺陷会累积。Figure 13 显示 VDM 的坍缩更早发生，并且持续累积；VLM 的坍缩更少，初始阶段后大体保持稳定。

这也提醒我们，3D agent 的世界模型不能只评估短 rollout。一个规划智能体需要的是可反复查询、可长时间展开的 dynamics prior，而不只是短视频生成器。

### 容易误读的地方

第一，不要把这篇读成“代码生成一定优于视频生成”。VLM 的优势有条件：它有程序 scaffold，有可选结构化配置，有 best-of-N 选择，而且数据本身来自仿真代码。换成自然视频或没有明确 MPM 先验的世界，结论可能变化。

第二，不要把 VDM 的 mIoU 优势读成“视频模型更懂物理”。mIoU 主要反映前景占据，不能保证运动因果、物体持久性或材料守恒。论文用 anomaly、collapse 和 W-MAE 正是在补这个盲点。

第三，数据集叫 MPMWorlds，但它是二维 MPM 世界，不是完整三维世界。它适合做物理推理诊断，不应直接外推到 3D 场景生成或真实机器人操作。

### 复现注意点

复现这篇需要三类资源。第一是数据生成与渲染环境：Taichi MPM、结构化 YAML 配置、渲染和视频处理。

第二是模型训练：VLM 使用 Qwen2.5-VL-7B-Instruct 做全量监督微调，VDM 使用 LongCat 做视频续写，并用 LoRA 适配。

第三是评测脚本：需要实现 mIoU、OCS、W-MAE、CTV、时间异常率以及前缀 best-of-N 选择。

算力方面，source_map 记录的实验计算为 `4× NVIDIA RTX A6000`，约每个模型 `12` 小时。真正的复现风险不只在训练，而在数据筛选和指标实现。尤其是 OCS、W-MAE 和时间异常率都是自定义指标，若阈值、颜色分割或时间窗口不同，结论强度可能变化。

## 局限

1. 数据是二维合成 MPM，不包含真实世界的纹理、遮挡、三维视角、传感器噪声和接触复杂性。
2. 材料覆盖仍有限。作者明确提到没有头发、布料和高刚度物体等真实世界重要材料。
3. 因为所有视频都由 ground-truth simulation code 生成，基准可能天然偏向代码生成路线；自然视频中是否仍然如此并未证明。
4. VLM 的结论依赖 scaffold、结构化配置和 best-of-N 推理预算。若只给单次开放代码生成，稳定性可能下降。
5. VDM 只使用一个 14B LongCat baseline。更强的视频模型或更好的结构化条件注入方式可能改变对比。
6. 指标虽然比像素误差更物理，但仍是视觉近似指标，没有直接评估粒子轨迹、能量守恒或真实物理参数误差。
7. 数据集还没有扩展到 3D、真实可变形物体或自然语言侧信息，因此对现实 agent world model 的支撑仍是间接的。

## 我的笔记

这篇可以作为后续写 3D agent / 4D world model 相关工作的一个“评测设计参考”。我最想借用的不是 MPM 本身，而是它的拆解方式：给模型同一段视觉前缀，再逐步给材料、位置和完整配置，看模型到底在哪种信息上失败。

如果以后做面向 agent 的 3D 世界模型，我会考虑把评测分成三层。第一层是视觉状态估计：能否恢复对象、几何、材料和速度。第二层是动力学展开：给定正确状态，能否长期保持物体和材料一致。第三层是规划可用性：世界模型的错误是否会改变 agent 的动作选择。MPMWorlds 基本覆盖前两层，但第三层还没有做。

这篇也解释了为什么“代码世界模型”和“视频世界模型”应该融合。代码提供长时序结构，视频提供视觉状态估计。一个更理想的系统可能是：VDM 或视觉模型先抽取几何和材料状态，VLM/仿真模块生成可执行动力学，最后再用视频模型补充渲染细节。Table 1 的 gate 已经暗示这种组合比单一路线更稳。

和 Code2Worlds 放在一起看，会形成一条很清楚的线：Code2Worlds 试图从语言生成开放四维仿真；MPMWorlds 则问这些仿真/视频系统是否真的能推断和外推物理。如果要写相关工作，可以把它们分别放在“程序化世界生成”和“物理外推基准”两个位置。
