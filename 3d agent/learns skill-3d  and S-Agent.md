> 写给**人工智能新人**。两篇论文乍看几乎是一回事（都让大模型当「规划器」、配几何工具、加记忆、再蒸馏进 Qwen3-VL 小模型），但**真正的创新点完全不同**。这份笔记的任务就是：把这两篇放在一起，**逐维度讲清它们到底差在哪**，并用类比让你一眼记住。

## 0. 一分钟速览：一句话区别

> **Skill-3D 的灵魂是「技能」——把「某类场景该怎么用工具」抽象成可复用、会自我进化的 SOP 手册，跨题积累、检索复用。**
>
> **S-Agent 的灵魂是「时空证据累积」——在解一道题的过程中，用 L1/L2/L3 三层工具逐步把视觉变成可比的三维关系，并用双记忆把「当前这道题」的证据攒起来，尤其面向多视角/视频。**

🔑 **一句类比记住它**：

- **Skill-3D 像「老侦探的私人手册库」**：他破过的每一类案子都沉淀成一页 SOP（「遇到房间级测距，先检测→深度→重建」），还把翻过的车记成红字警告。新案子来了，他**先翻手册**找最对的那一页。重点是**跨案子的经验抽象与复用**。
- **S-Agent 像「侦探办当前这一个案子的工作台」**：他把这个案子的线索一层层往上垒——先圈出物证（L1）、再测距定位还原三维（L2）、再让各路专家把几何翻成「A 在 B 左前方」（L3），并随时把已确认的线索钉在白板上（记忆）。重点是**单个案子内、跨时间/视角把证据攒齐**。

两者**不是竞争同一个点，而是各自押注在不同的"难点"上**：Skill-3D 押"策略复用与进化"，S-Agent 押"证据的层级化与时空累积"。

## 1. 先各自速写一遍（确保新人有共同基线）

### 1.1 Skill-3D 在做什么

诊断：现有工具增强智能体对千差万别的 3D 场景用**一刀切**工具策略 → 证据错配、冗余调用、提升有限。

解法：把"在某类场景、对某类问题、该用哪些工具、按什么顺序"显式学成**技能（skill）**，存进**技能库**，在线时**检索**最匹配的技能来引导工具规划。技能分两类——**静态**（8 条人工种子 SOP）和**动态**（从模型自己跑题轨迹里挖出来的，带成功率/奖励和失败教训）。**Scene Memory（成败卷宗）**与**Skill Library** 之间**共同进化（Co-Evolve）**：成功 rollout → 提炼成 workflow，失败 rollout → 记成 lesson，写回库里，越用越准。最后用 **Agentic SFT + GRPO**（奖励 = 0.6 答对 + 0.2 工具质量 + 0.2 格式）把这套本事蒸馏进 Qwen3-VL-4B/8B。

招牌结果：闭源 4 模型平均 VSI 42.9→64.5（+50.3%）；**ETU（有效工具使用率）VSI 39.2→78.7%**；消融显示**技能检索最关键**（去掉它从 69.9 掉到 64.1，跌幅最大）。

### 1.2 S-Agent 在做什么

诊断：VLM 有"语义→几何"的断裂——能描述图里有什么，但不会自然形成关于图像流背后**三维场景的持续证据**；而真实空间推理常依赖**隐藏、变化、跨视角**的证据。

解法：把空间推理重写成**主动的证据累积过程**。VLM 当**语义规划器**，每一步决定"下一步该定位谁、验证什么关系、算哪类三维信号、还是已经够了"；工具按**三层金字塔**组织——**L1**（关键帧搜索、视觉定位、开放词表检测、验证、轻量深度）把模糊指称变成框/标签/可见性；**L2**（度量深度、三维坐标、相机位姿、鸟瞰/新视角）把二维提升到共享三维；**L3**（计数、相对方向、朝向、度量测量、物体中心视角专家）把原始几何**翻成可读的语言关系**。再加**双记忆**——**Scene Memory**（本题相关的实体/位置/关系的紧凑动态状态）+ **Agent Memory**（规划思路/工具调用/观测/失败/中间结论）。最后用 S-Agent 生成的轨迹做 **S-300K**，**SFT 蒸馏**出 S-Agent-8B（Qwen3-VL-8B-Instruct）。

招牌结果：零样本 **MMSI 平均 46.4**（> Gemini 3 Pro 45.2、> GPT-5.4 41.9）；**ViewSpatial 平均 60.0**（比 GPT-5.4 高 14.4）；ReVSI 58.8（第二，略低于 Gemini 3 Pro 60.9）。消融（ViewSpatial）：L1+L2 = 49.8 → **加 L3 跳到 56.7（最大一跳）** → 加双记忆到 Full 60.0。蒸馏：S-Agent-8B 比 Qwen3-VL-8B-Instruct，MMSI 31.1→41.6、ViewSpatial 42.2→46.8、ReVSI 49.1→52.8。

## 2. 最根本的区别：中心抽象不同（这一节最重要）

如果你只能记住一件事，记这个：**两篇都有"记忆"，但"记忆"指的根本不是一回事；两篇都用工具，但"工具的组织逻辑"也不一样。**

### 2.1 区别 A —— Skill-3D 的记忆是「跨题的策略」，S-Agent 的记忆是「本题的证据」

这是最容易把新人绕晕的点，因为**两篇都用了 "Scene Memory" 这个词**，但含义相反：

| | **Skill-3D 的 Scene Memory** | **S-Agent 的 Scene Memory** |
|---|---|---|
| 存什么 | 过去**每一道题**跑完的 episode（问题、任务类、成败、奖励、工具链、错误模式） | **当前这道题**已确认的实体/位置/关系/多视角观测 |
| 粒度 | **跨题、抽象**（用来挖"这一类问题的套路"） | **本题、具体**（这一个场景目前长什么样） |
| 生命周期 | **持久**，越攒越多，喂给 Skill Manager 提炼技能 | **随题重置**，是解题时的"工作台白板" |
| 目的 | 学**怎么解这一类**（procedural / 策略） | 记**这一个解到哪了**（working memory / 状态） |

🔑 **类比**：
- Skill-3D 的"记忆"= **侦探的历年办案档案室**，目的是从中**总结出可复用的破案手册**。
- S-Agent 的"记忆"= **侦探办当前案子时的那块白板**，目的是**别忘了刚查到的线索**。

> Skill-3D 也有"本题内的推理轨迹"（think/tool_call 协议），S-Agent 也算是有"跨题的学习"（蒸馏成 S-300K）。但**各自命名、各自强调的那块记忆，押注完全相反**：Skill-3D 押"跨题抽象出的技能"，S-Agent 押"本题内累积的证据 + 推理轨迹（Agent Memory）"。

### 2.2 区别 B —— 工具：Skill-3D 是「扁平池 + 技能选谁」，S-Agent 是「L1/L2/L3 三层金字塔」

- **Skill-3D**：6 个工具（Depth-Anything-3、GroundingDINO、SAM3、Pi3、SwinIR、Orient-Anything-v2）是**平铺**的一个池子。**谁来决定用哪个、什么顺序？——检索出来的技能。** 创新点在"**选**对工具链"。
- **S-Agent**：工具被**显式分成三个抽象层级**，体现"证据从二维→三维→关系"的提升过程：
  - **L1 二维感知**：关键帧搜索、视觉定位、开放词表检测、验证、轻量深度 → 产出框/标签/可见性/粗位置。
  - **L2 三维提升**：度量深度、3D 坐标、相机位姿、鸟瞰/新视角 → 把对象拉进**共享三维坐标**好比较。
  - **L3 空间专家**：计数、相对方向、朝向、度量测量、物体中心视角 → 把几何**翻译成语言关系**（"在左""朝前""从那个视角看是…"）。创新点在"**把证据组织成层级、逐层抽象**"。

🔑 **类比**：Skill-3D 是"**一柜子工具 + 一本说明书告诉你这活儿该拿哪几把**"；S-Agent 是"**一条流水线，毛坯（像素）从一楼（2D）送到二楼（3D）再送到三楼（关系），每层加工一道**"。

> 注意一个**深刻的呼应**：S-Agent 的 ablation 显示 **L3 专家带来最大一跳（49.8→56.7）**——也就是说，真正让 VLM 受益的不是给它原始深度/坐标，而是**把几何翻成"任务相关的关系"**那一步。这一点 Skill-3D 也认同（它的工具奖励逼模型把证据真用上），而且——**这恰好就是你自己 training-free 实验的核心结论**（见 §6）。

### 2.3 深入理解：「L1/L2/L3 层级证据 + 时空累积」到底是什么（带例子）

这个短语其实把**两个不同的维度**塞在了一起，拆开就清楚了：

> **「L1/L2/L3 层级证据」管的是"空间维度——证据被加工到多深"。**
> **「时空累积」管的是"两条轴——证据在空间上拼、在时间上攒"。**

把它想成一张二维网格：**纵轴 = 加工层级（L1→L2→L3，越往上越"熟"）；横轴 = 时间/视角（视频一帧帧看过去，证据越攒越全）**。

#### (1) L1/L2/L3 层级证据：把"看到的"逐层加工成"能用的"

🔑 **类比：一条加工流水线**。原料是像素（生的），成品是关系词（熟的），中间过两道工序。

**例题**：一段厨房第一人称视频，问「**从洗碗机的位置朝水槽看，冰箱在你左边还是右边？**」

| 层 | 干什么 | 在例子里产出什么 | 为什么需要它 |
|---|---|---|---|
| **L1 二维感知** | 在像素里"圈东西" | 关键帧搜索找到"有洗碗机+水槽"的帧#12、"有冰箱"的帧#40；检测/定位框出三个物体，给出 **2D 框+标签** | 先得知道"谁在哪个画面的哪个位置" |
| **L2 三维提升** | 把 2D 框"抬"进三维 | 估**度量深度+相机位姿**，算出三物体在**同一套房间坐标**里的 3D 位置：冰箱(2.1, 0.5)、水槽(1.0, 3.0)、洗碗机(1.2, 3.5) | 2D 框不能比"左右"，必须先有共享三维坐标 |
| **L3 空间专家** | 把几何**翻成关系词** | 相对方向专家拿"洗碗机位置+朝向(朝水槽)+冰箱位置"，做坐标系旋转，输出 **"冰箱在你右边"** | LVLM 读不动坐标，只读得懂关系词（正是你 GEM 线证明的） |

**为什么叫"层级证据"**：同一份信息，L1 给"框"（最生）、L2 给"坐标"（半熟）、L3 给"在右边"（全熟）。**越往上越抽象、越接近答案**。S-Agent 消融里 **L3 带来最大一跳（49.8→56.7）**，就是因为只有到 L3，证据才变成 LVLM 真能用的形式。

#### (2) 时空累积：为什么不能"一次看完就答"

关键事实：上例里**洗碗机和冰箱根本不在同一帧**（洗碗机在帧#12、冰箱在帧#40）。这就逼出了"时空"两个字：

- **"空间"累积**：把帧#12 的洗碗机坐标、帧#40 的冰箱坐标，**用相机位姿对齐到同一房间坐标系**，拼成一张完整"房间地图"——证据在**空间上拼**。
- **"时间"累积**：不是看一眼就够，而是**一帧帧往下看**，每见新东西就补进地图，看得越多地图越全——证据在**时间上攒**。

🔑 **类比**：你蒙着眼被领着在房间里走，每走一步摘下眼罩瞄一眼（一帧），记住"这里有冰箱"。走完一圈，脑子里就拼出整个房间布局——**没有任何一眼能看全，但一路攒下来就全了**。这张"脑内地图"就是 **Scene Memory**（本题工作台白板）。

#### (3) 合起来看：一张图

```
                    时间 / 视角  →→→→→→→→→→→→→→→→
                  帧#12            帧#40           ...
                ┌──────────────┬──────────────┬──────
   L3 关系  ↑   │              │              │   →「冰箱在你右边」(攒齐后才算得出)
   ─────────    │              │              │
   L2 三维  │   │ 洗碗机(1.2,3.5)│ 冰箱(2.1,0.5) │   ← 用相机位姿对齐到同一坐标系
   ─────────    │ 水槽(1.0,3.0) │              │
   L1 二维  │   │ 框出洗碗机/水槽 │ 框出冰箱      │   ← 各帧各自先圈出物体
                └──────────────┴──────────────┴──────
   纵轴=层级(加工多深)          横轴=时间(看了多少帧)
```

- **纵向**（一列内往上）= L1/L2/L3 层级证据：把这一帧的像素加工成坐标/关系。
- **横向**（跨列）= 时空累积：把不同帧的坐标对齐、攒进同一张地图，直到够回答。
- 每攒到一点就钉进 **Scene Memory**（地图）和 **Agent Memory**（查过哪几帧、做过哪些事），所以最后答题不用重看整段视频。

#### (4) 和普通 VLM 对比（凸显这套设计的意义）

| | 普通 VLM | S-Agent |
|---|---|---|
| 看视频 | 抽几帧**一次性**塞进去直接答 | **一帧帧主动找证据**，逐层加工、跨帧对齐攒进记忆 |
| 跨帧物体 | 洗碗机/冰箱不同帧 → 脑内对不齐 → 蒙 | 用相机位姿显式对齐到同一坐标 → 算得准 |
| 证据形式 | 给像素，模型自己脑补几何（脆） | L3 把几何翻成"在右边"（LVLM 读得懂） |

> 🔑 **一句话**：**「层级证据」是"把一帧像素逐层加工成关系词"（纵向、空间内）；「时空累积」是"把多帧/多视角证据对齐攒成一张活地图"（横向、跨时间）。两者合起来，VLM 才能回答那些"任何一眼都看不全"的空间问题。**

### 2.4 追问：视频帧数特别长时，记忆怎么不爆、少丢信息？

> 这是 §2.3「时空累积」最自然的追问——视频几千上万帧，记忆不会爆吗？关键认知先记住：

> **S-Agent 处理长视频，根本不靠"把所有帧塞进上下文窗口"。所以它面对的不是"如何无损压缩超长上下文"，而是用一种表示把"帧数"这个变量直接从等式里消掉了。**

🔑 **一句话类比**：普通长上下文像「**把 4 小时会议录音逐字稿全塞给你**」——一长就爆、就丢；S-Agent 像「**记会议纪要**」——纪要长度取决于"讨论了多少实质内容"，**不是"开了多久"**。

#### 三道防线（为什么帧数变长、记忆不跟着爆）

| 防线 | 机制 | 效果 | 论文依据 |
|---|---|---|---|
| **一、关键帧检索** | L1 在长流里**只挑可能含证据的帧**，不平等处理每一帧 | 几千帧空镜头根本不进流程；**按需取**而非一次性全编码 | 明说（Appendix B 关键帧搜索） |
| **二、Scene Memory 存符号状态，不存帧/像素** | 只存**实体+3D 坐标+关系**的紧凑状态；同一物体跨帧**关联合并成一条**（计数专家跨帧聚合、避免重复计数）；新观测**增量合并/精化**而非追加 | **记忆大小 ≈ 不同物体数，而非帧数/检测次数** | 明说（"compact, not full dense reconstruction"；计数专家去重） |
| **三、原始帧仍在、可回查** | agentic 闭环，证据不够就**再查某几帧/再调工具** | 压缩**有损但可补救**（纪要没写的能翻回录音段落） | 框架机理 |
| 配套：双记忆分工 | Agent Memory 记"已查过哪几帧、做过什么" | 不重复看已看过的帧；轨迹可裁剪而不丢"做到哪了" | 明说 |

**核心洞察(防线二)**：空间推理真正需要的信息量，被**场景复杂度**上界，**不被时长**上界。一个厨房就那么多家具，拍 10 分钟还是 4 小时，家具数量不变 → Scene Memory 大小基本不变。

🔑 类比：逛宜家样板间，你脑里记的是"客厅有沙发+茶几+电视墙"这张**布局图**，不是拍的 200 张照片。布局图大小取决于房间里有多少东西，跟拍了多少张照片无关。

#### 诚实边界（它**不是**真无损，"少丢"是换来的）

1. **关键帧检索会漏（recall 问题）**：没挑中含关键证据的帧 → 这条信息**真的丢了**，记忆再好也补不回。这是最现实的失败点。
2. **Scene Memory 按"当前问题相关"裁剪 = 设计上有损**：原文 "question-relevant... state **needed for the task**"——**当时没判为相关、后来才要用**的信息可能没存。
3. **强时间累积型任务仍未解决**：附录 VSI-SUPER 上 **VSC（长视频空间计数）所有系统都很低**——"在 4 小时里累计数清出现过多少个某物"这类**强依赖完整时间累积**的任务没攻克；它强的是 VSR（关系靠"最终布局"就能答，不那么依赖时间累积）。
4. **作者自己对 VSI-SUPER 可靠性持保留**（数字当补充证据看）。
5. **精细的记忆淘汰/总结算法，这份转述未展开**——上面是设计原则 + 通用机理，不是逐行实现；复现这块需自定策略（或回查 PDF 正文）。

> 🔑 **总结**：**S-Agent 先用关键帧检索"少看"，再把像素蒸成"物体+坐标+关系"的紧凑符号状态——其大小由场景复杂度（有多少东西）而非视频时长（多少帧）决定，所以帧数再长也不爆。代价：检索可能漏帧、按相关性裁剪有损、强时间累积任务（如长视频计数）仍吃力。**

## 3. 逐维度详细对照

### 3.1 控制流：技能检索 vs. 规划器直接决策

- **Skill-3D** 有一套**重型检索机件**，这是它工程上的标志：
  1. 把每条技能模板化成"自我介绍"检索文本；
  2. **稠密召回**（问题 vs 技能向量余弦相似，Top-K）；
  3. **多因子精排**（语义 0.45 + 类型匹配 0.20 + 工具对路 0.15 + 战绩/新鲜度/失败惩罚…）；
  4. **MMR 去重**（留"相关又互补"的一组）；
  5. **MLLM 拍板**（在 `<skill_choice>` 里选一个）。
  还有 **Skill Manager** 的晋升门槛（成功 + 奖励≥0.3 + 有有效工具链）和合并/新建判断。
- **S-Agent** 没有技能检索。规划器**直接**根据 `(q, F, Scene Memory, Agent Memory)` 算出下一步请求 $r_t = \pi_\theta(q, F, S_t, H_t)$，工具返回 $o_t$ 后更新两类记忆 $(S_{t+1}, H_{t+1}) = \text{Update}(S_t, H_t, r_t, o_t)$。控制流更**轻、更直**，靠规划器和记忆闭环，而不是靠一个外部技能库。

🔑 一句话：Skill-3D 在"**调工具之前先查手册选策略**"上下了重注；S-Agent 把这件事交给规划器**临场判断**，把重注下在"**证据怎么分层、怎么攒**"上。

### 3.2 训练方法：SFT + GRPO（含强化学习）vs. 仅 SFT 蒸馏

| | Skill-3D | S-Agent |
|---|---|---|
| 阶段一 | Agentic SFT（teacher = GPT-5.4 轨迹，只采训练集） | SFT 蒸馏（teacher = S-Agent 框架轨迹） |
| 阶段二 | **GRPO 强化学习**：同题采 G=8 解，组内相对优势 $A_i=\frac{r_i-\text{mean}}{\text{std}}$，KL 正则 β=0.05 | **无**（只 SFT 1 个 epoch） |
| 奖励 | $r = 0.6\,r_{acc} + 0.2\,r_{tool} + 0.2\,r_{format}$，工具奖励带预算惩罚 | 不适用（无 RL） |
| 训练细节 | 两阶段，含 RL，强调"治证据错配/冗余" | LLaMA-Factory，seq 8192，lr 5e-5，cosine，3% warmup，1 epoch，8×B200 |

> 这是一个**实打实的差别**：Skill-3D 用 RL（GRPO）去**强化"该调工具就调、别冗余、格式要对"**这种行为；S-Agent 不做 RL，靠**高质量轨迹的纯监督模仿**。S-Agent 的赌注是"**轨迹本身就是好监督**"——它把每条轨迹拆成三种互补格式（见 3.4）来榨干监督信号。

### 3.3 蒸馏规模：4B/8B 双规格 vs. 仅 8B

- **Skill-3D**：同时放出 **4B 和 8B**（+59.7% / +60.3%），8B（58.8）甚至反超用工具的 GPT-4o。
- **S-Agent**：只蒸馏 **8B**（S-Agent-8B）。
> 对你（受 GPU 限制、只用 4B）很关键：**Skill-3D 有现成 4B 复现路径，S-Agent 没有官方 4B**。若想在 4B 上复刻 S-Agent，得自己缩规模。

### 3.4 数据集：无命名集 vs. S-300K（这是 S-Agent 的独立贡献）

- **Skill-3D** 不发布命名 SFT 集，沿用 Think3D 的"每类题随机 30% 当训练、其余问题级互斥当测试"。
- **S-Agent** 把**数据集本身**做成一项贡献——**S-300K**：100,000 条原始 agent 轨迹 → 质量过滤剩 **51,596** 条 → 拆成三种互补监督格式，合计 **292,391** 条 SFT 样本：
  - 完整最终答案轨迹 51,596 条；
  - **回合级**轨迹 154,590 条（一个规划回合 = 一条样本）；
  - 非平凡**工具/专家**轨迹 86,205 条。
  > 🔑 注意 "300K" **不是 30 万道独立题**，而是 5 万多条有效轨迹**拆解**出来的多形态监督样本。这种"一条轨迹拆三种监督"的做法本身是个可借鉴的工程技巧。

### 3.5 评测基准与指标：几乎不重叠

| | Skill-3D | S-Agent |
|---|---|---|
| 基准 | VSI-Bench、BLINK、CV-3D、**MMSI** | **MMSI**、ViewSpatial-Bench、ReVSI、VSI-SUPER（长视频） |
| 唯一重叠 | **MMSI** | **MMSI** |
| 特色侧重 | 度量距离/尺寸/计数/房间尺寸（VSI 全谱） | **视角依赖**推理（ViewSpatial 的相机视角 vs 人视角）、长视频 |
| 标志指标 | **ETU**（有效工具使用率：既执行有效又真被用上，按总调用归一） | 基准自带（acc；VSI-SUPER 用 VSR/VSC） |

> **ETU 是 Skill-3D 独有的"诚实指标"**：它专门量"证据有没有被浪费"，直接回应"冗余调用"的动机。S-Agent 没有等价指标，主要看终答准确率。
>
> **ViewSpatial 是 S-Agent 的特色战场**：它专测"从相机视角看 vs 从人视角看"的方向差异（视角转换），S-Agent 在这上面零样本 60.0、比 GPT-5.4 高 14.4，是它最亮的胜场。Skill-3D 没碰这个维度。

### 3.6 "进化" vs. "一次成型"

- **Skill-3D** 的标题词就是 **Evolving**：技能库会**自我更新**——成功提炼 workflow、失败提炼 lesson，下次用更新后的库，**手册越用越厚、越用越准**（红字警告"遇 X 别用 A 改用 B"）。这是一个**持续学习 / 自我纠错**的回路。
- **S-Agent** **没有**自我进化的库。它的"学习"是**一次性**的：跑出轨迹 → 过滤 → SFT 一次 → 定型。推理时不再往一个会成长的库里写东西。

🔑 类比：Skill-3D 的手册是**活页本，边办案边加页改页**；S-Agent 是**印好的教科书，学一遍就固定**。

## 4. 别忘了——它们的相同点（避免新人以为天差地别）

正因为它们底层范式高度一致，对比"区别"才有意义。共同点：

1. **同一个诊断**：VLM 语义强、几何弱，自己估不准 3D，要靠外部几何工具补。
2. **同一个角色设定**：VLM 当**规划器/控制器**，不是一次性答题器；工具产出**可读证据**而非隐向量。
3. **同样有记忆模块**（尽管含义不同，见 §2.1）。
4. **同样两条腿走路**：①训练-free 包裹强模型就能涨；②再蒸馏进一个小 Qwen3-VL。
5. **同样从强 teacher 引导轨迹**（Skill-3D 明确 GPT-5.4；S-Agent 用 S-Agent 框架包强规划器）。
6. **同样发现"把几何翻成关系/结构化语言"才是工具增益的关键**（Skill-3D 的工具奖励 + ETU；S-Agent 的 L3 专家最大一跳）。
7. **同期、同领域**（2026-06），都用 Qwen3-VL 系骨干。

## 5. 一句话各自"不可替代"的贡献

- **Skill-3D 不可替代的是**：一个**会进化的技能库 + 一整套技能检索/晋升机件 + GRPO 把"会选工具"强化进 4B/8B**，并用 **ETU** 把"证据没被浪费"量化出来。**关键词：技能复用、自进化、RL、效率诚实指标。**
- **S-Agent 不可替代的是**：把空间证据**显式分成 L1/L2/L3 三层**、强调**跨时间/视角的时空累积**、双记忆（场景状态 + 推理轨迹）、面向**长视频与视角依赖**任务，并贡献了**S-300K** 这个命名数据集。**关键词：层级证据、时空累积、视角/视频、数据集。**

## 6. （加分）与你自己 training-free 实验的呼应——这点很关键

你做的 GEM 线（见 `Desktop/Skill-3D/infos/learn20260624.md` Part B）核心结论是：

> **给 LVLM 喂几何，"表示"决定一切**——原始矩阵/裸坐标≈噪声，**唯有翻成"关系词/带解读键的自然语言"才有用**；LVLM 自己做不动"世界→ego 坐标系旋转"，所以**object-level GEM 应输出关系词，把几何变换交给确定性代码 solver**。

**S-Agent 的设计从架构层独立印证了你的发现**：

- S-Agent 的 **L3 专家**"把原始几何**转换成语言化关系**（左/右、前/后、朝向、从另一视角看…）"——这正是你说的"输出关系词、别输出坐标"。
- S-Agent 的 **ablation：L3 带来最大一跳（49.8→56.7）**，而 L1/L2（原始 2D/3D 信号）只是铺垫——这正是你说的"**喂原始坐标没用，喂关系才有用**"的强证据，而且是在**真实 benchmark 全量**上、用**完整框架**得到的，比你文本探针的样本更大、更有说服力。
- S-Agent 论文自己的总结："VLMs benefit from tools most **when tool outputs are structured into task-relevant relations**"——几乎是你 B3.1 结论"**怎么喂 > 喂什么**"的另一种措辞。

🔑 **对你的研究的意义**：
1. **你的微观机制解释了它的宏观设计**。你从"逼问 LVLM 几何边界"的角度，**精确定位**了为什么坐标没用、关系才有用（卡在 ego 旋转的合成、负坐标×约定）；S-Agent 从系统角度**直接采用**了"输出关系"的方案并验证有效。两条线对到了同一句话上。
2. **但 S-Agent 没回答你回答的那个"为什么"**。它只是经验上发现"L3 关系专家最有用"，**没有做表示对照/反事实/oracle 闸门去证明"LVLM 读不了坐标、只读得了关系"这个因果**。**这正是你工作的差异化价值**——你的护栏化探针给了它的设计一个**机制级解释**。
3. **可操作的下一步**：你的"关系 vs 坐标"结论 + S-Agent 的 L3 专家清单，可以合起来定义你 object-level GEM 工具**到底该输出哪些关系字段**（相对方向、朝向、物体中心视角…），且**别输出原始坐标**。S-Agent 的 L3 专家列表几乎就是一份现成的"该输出什么"清单。
