# StateFlow: Building, Evolving, and Accessing 3D World States for Previsualization

## 核心信息

- **论文要解决的问题：** 预可视化不是一次性生成漂亮视频，而是反复改场景、改动作、改镜头并检查结果。现有 text-to-image/video 把所有变量压进一次生成，缺少可编辑的共同状态。
- **核心答案：** 用对象中心、持久的结构化 3D world state 作为创意与生成模型之间的工作层；视频只是从该状态渲染出的高保真观测。
- **系统组成：** State Construction、State Evolution、State Access 三阶段。
- **实验结论：** 结构和时间一致性明显领先，VBench 平均分 0.8484；场景 CLIP-I/CLIP-T 为 0.788/30.214；但实时性受第三方模型推理速度限制。

## 原文摘要翻译

StateFlow 把生成式预可视化定义为持久 3D 世界状态建模。它用可编辑 3D 世界组织场景结构、演化和摄像机，通过双视图初始化解决外观与布局冲突，通过意图驱动的结构化状态转移实现局部编辑，再通过渲染反馈修复摄像机轨迹。这样同一世界可以服务于视频创作、镜头规划、自由视点观察和游戏原型。

## 创新点

1. **问题重述：** 从 one-shot visual synthesis 转到 persistent world-state modeling，抓住了 previs 的真实工作对象。
2. **双视图的职责分解：** front view 负责身份、外观和资产，BEV 负责地面布局、拓扑和空间支撑；VLM 只用于冲突判断与先验，不是把两张图盲目拼接。
3. **状态级编辑：** 通过 $(g_i,p_i,s_i)$ 三元组选择性更新几何、姿态和语义，而不是每个 edit 都重新生成整个世界。
4. **渲染闭环摄像机：** VLM 先提议，渲染器暴露可见性、构图、碰撞和运动问题，局部修复后再选轨迹。

## 一句话总结

StateFlow 的实质贡献不是又一个视频生成器，而是把“可反复修改的 3D 制作状态”显式化，再让图像/视频模型作为资产和观测工具接入这个状态。

## 研究问题

论文围绕三个问题展开：如何从单个自然语言提示初始化一个可信的多物体 3D 世界？如何在不破坏已有身份和空间关系的情况下执行扩展、风格变化、运动和毁坏事件？如何从世界状态规划镜头，使镜头在真实几何中可见、无碰撞且符合导演意图？

## 数据与任务定义

输入是单个文本 prompt；没有专门训练 StateFlow 的新数据集。状态表示为：

$$W^t=\{o_i^t\}_{i=1}^{N_t},\qquad o_i^t=(g_i^t,p_i^t,s_i^t).$$

其中 $g$ 是几何/资产，$p$ 是 3D 位置与姿态，$s$ 是类别、外观、动态状态等语义属性。系统使用 Gemini 3.1 做理解、意图解析、布局推理、状态计划与摄像机反思；Nano Banana 2 生成正面与 BEV 参考；Hunyuan3D 生成对象资产；Seedance2 负责视频输出。

## 方法主线

### 机制流程

1. **构建：** 从 prompt 生成 front view 和 BEV；检测实例和布局框；匹配对象。front-only 对象作为语义锚点，BEV-only 对象由 VLM 判断是否合理；明显幻觉降权或移除。
2. **提升：** VLM 给出 grounded/floating 先验，把 BEV 框和尺寸先验提升成 3D 框；用 $L_{front}$、$L_{bev}$、$L_{vlm}$、$L_{phys}$ 做推理时轻量优化，只改 box 参数。
3. **资产化：** front-view crop 经 image-to-3D 获得 $g_i^0$，与 $p_i^0,s_i^0$ 合成 $W^0$。
4. **演化：** `Plan_VLM(W^t,u^t)` 生成紧凑 $\DeltaDelta^t$。场景扩展复用构建器；风格变化改描述符；刚体运动改 $p$；爆炸/毁坏等难连续模拟的事件替换 $g$；外观和状态改 $s$。
5. **访问：** VLM 根据状态、渲染视图和导演意图提出 $\Deltapi_i^0$；低成本渲染后评估 intent match、visibility、framing、collision、motion；围绕问题做局部修复，不做全局轨迹搜索。

### 为什么这种分解有效

论文把最容易互相干扰的变量拆开：场景构建关注世界“是什么、在哪里”，状态演化关注“如何改变”，摄像机规划关注“如何看”。这使得视频模型不再承担长期身份、布局和镜头几何的全部记忆负担。

## 关键结果

### 主结果与强基线

- **视频（VBench）：** StateFlow 的 Average = **0.8484**，高于 Seedance2.0 0.8387、Wan2.2 0.8283、Animaker 0.8092、MovieAgent 0.8075；Subject Consistency = 0.9135、Background Consistency = 0.9506、Motion Smooth = 0.9923、Flicker = 0.9902 均为最高。
- **场景：** CLIP-I = **0.788**、CLIP-T = **30.214**，均高于 SynCity 的 0.689/22.880；Q-Align Quality = 3.621，高于 3.535。
- **人评/MLLM：** 场景 Overall = 4.5/3.7，视频 Overall = 4.5/4.0；两种设置都领先。

这些结果支持“结构化状态对一致性和可控性有帮助”，但不能证明所有视觉质量维度都领先：HPS V2 的 0.151 低于 SynCity 的 0.175，审美/成像也不是全胜。

### 消融到底说明了什么

- **w/o BEV Layout：** 全局布局、尺度和物体关系变差，说明单靠外观不能恢复场景拓扑。
- **w/o Conflict Res.：** 出现缺失、重复、穿插或不合理摆放，说明两视图必须有显式冲突仲裁。
- **直接重生成替代状态转移：** 身份保持与跨编辑空间一致性下降，支持 persistent records 的必要性。
- **VLM-only Camera：** 会出现错误注视点、轨迹穿物体、过于简单的轨迹；渲染反馈是几何校验器而不是装饰模块。

## 深度分析

### 真正贡献是什么

真正贡献在表示与工作流边界，而非单个生成模型。系统把世界状态作为“可读写数据库”，把模型调用变成对数据库的构建、补丁和观测。对于 previs，这比单次生成的画质更接近生产需求：导演要能说“扩展区域、让飞船爆炸、从另一角度拍”，而不是重新描述整幅图。

### 容易误读的地方

1. “视频质量提升”不能理解为 StateFlow 自己训练了新视频模型；视频由 Seedance2 等外部模型增强。
2. “物理合理”主要来自尺寸/落地先验、碰撞和边界惩罚，不等同于连续物理模拟。
3. 论文将页面级可视化案例称为 game prototyping，但没有展示完整游戏引擎交互、性能或资产运行时评估。
4. MLLM 评估使用 gemini-3.1，同时系统实现也依赖 Gemini 3.1，存在评估器相关性风险。

### 复现注意点

需要 Gemini 3.1、Nano Banana 2、Hunyuan3D、Seedance2 的访问与版本；还需要把 VLM 的对象匹配、落地判断、状态转移 schema 和摄像机 checklist 固定下来。论文没有给出完整 prompt、权重、lambda 设置、运行时间分解、随机种子或公开评测脚本，严格复现会受限。场景实验是 wild inference，无 GT 3D，因此 CLIP/HPS/Q-Align 只能作为间接指标。

## 局限

- 第三方模型推理速度使系统仍不是 fully real-time。
- 依赖 VLM 的语义判断，错误会污染状态表；虽然物理损失可修复明显违规，无法保证真实尺度和复杂接触。
- front/BEV 双视图是互补但也可能互相矛盾；页面级文本和视觉案例没有给出冲突率或失败率。
- 事件级 asset substitution 对爆炸/毁坏有效，但不刻画连续破坏动力学。
- 用户研究每种设置 12 个 prompt、30 名参与者，覆盖面有限；MLLM 评分与人工评分有明显差异。

## 我的笔记

这篇论文值得放进“world model 作为制作中间层”而不是“视频生成 SOTA”这一脉络。它和 3D scene generation 的差别是有时间维度的 state update，和 embodied world model 的差别是目标不是策略学习或物理控制，而是导演可用的可编辑世界。可迁移的设计原则是：

- 先定义持久状态，再定义生成模型如何读写它；
- 把全局布局和局部外观用不同证据源约束；
- 对难以模拟的长尾事件，允许语义保持不变的资产替换；
- 让渲染/执行器提供反思证据，避免 LLM 只凭语言想象几何可行性。
