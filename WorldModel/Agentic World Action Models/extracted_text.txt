ABSTRACT
Recent world action models provide visual foresight and future prediction for
robot manipulation, but lack explicit mechanisms for compositional skill reuse.
Agentic robotics combines code-based planning and reasoning with reusable
skills, but often lacks predictive grounding in physical dynamics. We introduce
AW-0, an agentic world action model framework that integrates code-based plan-
ning with joint video and action prediction. We jointly model code, future video,
and robot actions as three coupled generative streams within a unified mixture-of-
transformers architecture. Within this architecture a code expert generates param-
eterized skill routines and control logic while video and action experts generate
future visual states and low-level motor commands. Code serves two comple-
mentary roles: it structures multi-step prediction and control within the world
model and represents skills as reusable programs for subsequent agentic execu-
tion. We further introduce an automated curation pipeline that labels robot and hu-
man video trajectories with aligned programs and consolidates recurring routines
into reusable skill libraries. Evaluations on RoboTwin 2.0 and physical bimanual
manipulation tasks show improved task performance over VLA and WAM base-
lines, alongside gains in language following, semantic reasoning and robustness,
demonstrating that agentic code enables connection between planning, prediction
and execution within WAMs.

INTRODUCTION
Learning-based robotic manipulation has progressed from small task-specific visuomotor policies
over a decade ago to broadly supervised foundation models that connect perception, language, and
action (Levine et al., 2016; Zitkovich et al., 2023; Kim et al., 2024; Niu et al., 2024; Black et al.,
2024; Bjorck et al., 2025; Niu et al., 2025; Liu et al., 2025; Black et al., 2025; Liu et al., 2026).
In parallel, self-supervised video prediction has long been valued as a learning signal to model the
world: image inpainting extended to video prediction led to action-conditioned video predictors that
can imagine the future before committing to an action (Pathak et al., 2016; He et al., 2021; Tong
et al., 2022; Finn et al., 2016; Assran et al., 2025; Ye et al., 2026).
World Action Models (WAMs) couple visual prediction with visuomotor policies, grounding control
in representations of how the physical world evolves (Ye et al., 2026; Kim et al., 2026; Yuan et al.,
2026). This predictive grounding is particularly valuable for complex manipulation, where success-
ful execution depends on anticipating object motion, contact, and the consequences of low-level
actions. Yet predicted video and action chunks do not by themselves specify how a long-horizon
task should be decomposed: which reusable skills to invoke, how to parameterize them, or how to
compose them across subtasks. Predicting the world and/or actions in general can also be expensive,
especially as it can be difficult to establish limits on how many degrees of freedom need to be “world
modeled” (or teleoperated, in the supervised setting).
Agentic robot systems provide complementary structure to WAMs: a programmatic harness that
selects reusable skills and tools, binds them to the current scene, tracks progress, and replans as
observations change (Liang et al., 2023; Fu et al., 2026; Zhang et al., 2026; Xiao et al., 2026; Lu
et al., 2026). This programmatic representation makes the structure of multi-step tasks explicit,
specifying which skills and tools to invoke, with what arguments, and in what sequence. Yet agentic
robotics often lacks predictive grounding in real-world physical dynamics and does not leverage a
learned model of how the world will change as the robot acts.
We advocate for an architecture that combines the foresight and action execution of WAMs with the
cognitive efficiency, reusable skills, and potential for future self-improvement of agentic robotics.
We propose AW-0, an agentic WAM framework that incorporates code-based planning and gen-
eration directly into world action modeling via a grounded code expert that harnesses broad pro-
gramming priors to synthesize modular skills featuring explicit parameters and control logic. Code
guides synchronized video and control modules within a mixture-of-transformers architecture, si-
multaneously denoising discrete code structures, predicted visual observations, and low-level motor
commands.
We first show that such agents can be realized by adding a code expert to a WAM, leveraging multi-
sensor action and code generation in a planning stage. We develop a modular generation framework:
planning via code generation significantly improves WAM performance, by appropriately condition-
ing the long-horizon generations required for complex robotic tasks. An automated curation pipeline
extracts systematic routines into reusable program libraries, mapping code segments directly onto
robotic and human video trajectories. This approach bridges high-level semantic reasoning with
predictive physical dynamics, establishing a unified language for compositionality across distinct
environments and tasks. We further demonstrate agentic skill reuse via a hybrid deployment strat-
egy that selects between raw action chunk execution and programmatic skill invocation. Empirical
evaluations across RoboTwin 2.0 benchmarks and physical bimanual setups show substantial perfor-
mance gains compared to standard VLA and WAM baselines, highlighting programmatic code as an
effective structural backbone for predictive planning, skill discovery, and embodied robotic control.
Our primary contribution is the conceptualization and realization of agentic robotic skills within
a world action model framework, showing that code generation improves action prediction in the
world model, and that the code generated from the world model can be re-used in an agentic frame-
work. Specific novel contribution elements include: a mixture-of-transformers framework integrat-
ing a code expert into world action models via simultaneous denoising of code, video, and control;
an automated agentic pipeline designed for program annotation and skill discovery; a dataset of such
structured skill programs; and a hybrid execution policy that dynamically toggles between program-
matic skill invocation and direct deployment of action chunks from the WAM action expert.

AGENTIC WORLD ACTION MODEL
We formulate AW-0 as a unified conditional generative model over code, video, and actions, which
respectively describe structured skill plans, future scene dynamics, and continuous robot motion.

as continuous video latents Z0 encoded by a pretrained variational autoencoder, and robot motion

2.1
MIXTURE OF TRANSFORMER ARCHITECTURE
As shown in Figure 2, AW-0 adopts a Mixture-of-Transformers (MoT) (Liang et al., 2025) archi-
tecture with three experts for skill planning, future visual prediction, and continuous control. Each

expert keeps its own attention projections (WQ, WK, WV , WO), layer normalizations, and FFNs,

Code Expert. The code expert augments a pretrained language backbone with a frozen Qwen3-

Video and Action Experts.
The video expert uses a video DiT initialized from Cosmos-
Predict2.5 (NVIDIA, 2025b) to model VAE-encoded future frames conditioned on observed frames,
while a separate action DiT generates continuous action chunks. Both experts receive language
embeddings through cross-attention, with additional robot-state conditioning for the action expert.

2.3
AGENTIC CODING IN WAM
Automatic Annotation Pipeline. We propose an automatic annotation pipeline (Figure 3) that
annotates the training data with skill planning code in three stages. We first sample one episode
per task and use Gemini 3.1 Pro (Google DeepMind, 2026) to write subtask-level skill programs
against predefined declaration-only APIs, while Claude Code running Claude Opus 4.8 (Anthropic,
2026) acts as a coordinator that distills recurring, task-general skills. We then freeze the skill library
and re-annotate the sampled episodes with the finalized vocabulary, forming a cache of reusable
subtask-to-program mappings. To annotate the remaining corpus, we reuse a cached program when
the subtask’s contact and motion pattern matches an existing entry; otherwise, the coding agent
generates a new annotation and adds it to the cache. See Appendix K for further pipeline details.

Code Usage in Model. Annotated programs define the interface through which the code expert
plans. During training, the code stream concatenates a conditioning prompt and the active slice, a
short block of primitive or skill calls. Only the slice is corrupted by the absorbing-mask process of
Eq. 4 and supervised by the masked-token loss. At each replanning point, the policy rebuilds the
prompt and appends a canvas of G mask tokens. The canvas is decoded jointly with the video and
action states over the T denoising steps, committing the G/T most confident masked positions per
step. By default, the decoded slice is not executed. It serves as a subtask plan that conditions the
action expert through joint denoising, while the predicted action chunk drives the robot.
Memory Cache. Since a single observation is often insufficient to reveal task progress, the code
expert receives a compact cache of the slices generated so far. The history slices are compressed
into K learnable memory slots and read back as prefix tokens before the prompt in the code stream.
During training, the buffer holds the preceding annotated slices, replaced with probability p by the
model’s own predictions. At inference, it is reset per episode and grows with each decoded slice.
Hybrid Actions. We additionally explore an inference mode in which the decoded code slice is exe-
cuted in the manner of Code-as-Policies (CaP) against a library of perception and control primitives,
and the executed actions are integrated with the direct actions of the action expert. At deployment,
the two channels are arbitrated at every replanning point: the decoded slice takes over the current
stage only if it passes a set of validity and progress checks; otherwise the action chunk from the
same forward pass drives the robot until the next replan. See Appendix I for the full algorithm.

3
EXPERIMENTS
We evaluate AW-0 on RoboTwin 2.0 (Chen et al., 2025) and 8 real-world tasks spanning parallel-
gripper and dexterous-hand embodiments, assessing language following, semantic reasoning, and
skill execution, as well as the robustness benefits of hybrid execution in variant scenarios.
Baselines. We compare four baselines: (1) π0.5 (Black et al., 2025), a state-of-the-art VLA with
strong semantic reasoning; (2) EgoScale (Zheng et al., 2026), a VLA pretrained on large-scale ego-
centric human data; (3) DreamZero (Ye et al., 2026), a WAM jointly generating future video and
actions; and (4) WLA (Yang et al., 2026), an autoregressive model jointly predicting textual sub-
tasks, subgoal images, and actions. All baselines and the default AW-0 configuration use the same
task-specific demonstrations for post-training and follow the same evaluation protocol. The sim-
ulation hybrid configuration uses separately collected CaP-generated demonstrations, as described
below. Baseline implementation details are provided in Appendix C.
3.1
SIMULATION EXPERIMENT
Benchmarks. We evaluate AW-0 on RoboTwin 2.0. Following the training-data requirements spec-
ified on the official RoboTwin 2.0 leaderboard1, we train on 50 clean demonstrations per task (2,500
episodes in total) and evaluate under the benchmark’s two settings: clean, with a clean tabletop,
plain background, fixed lighting, and no distractors; and random, with domain randomization over
background and tabletop textures, lighting, tabletop height, and distractor objects. We report the
mean success rate over 50 rollouts per task.
Hybrid Evaluation. We additionally evaluate AW-0 in the hybrid mode, in which the training
demonstrations are collected by executing CaP programs written against a set of CaP-X-style (Fu
et al., 2026) primitive APIs that we develop for RoboTwin 2.0. The programs are written automati-
cally by Claude Opus 4.8, following the agentic framework of ASPIRE (Lu et al., 2026).

exhibit complementary strengths. Overall, AW-0 achieves the highest average success rate of 50.7%
across both settings, outperforming all baselines including models designed for broad generalization.
The advantage comes mostly from the clean setting, where AW-0 reaches 80.8%, exceeding the
strongest baseline WLA (64.8%) by 16.0 points. Under visual randomization, performance drops to
20.6%, consistent with the challenges of pixel-level O.O.D prediction discussed in prior work (Yan

3.2
REAL-WORLD EXPERIMENT
Robot Platforms and Action Space. We conduct real-world experiments on two platforms: the
YAM station, a fixed-base bimanual setup with two 6-DoF arms and parallel grippers, and the
Tianji–Sharpa platform, a bimanual robot with two 22-DoF Sharpa dexterous hands. Both platforms
observe three RGB views and act in the unified 64-D state–action space defined in Appendix A.
Further details on the robot setups are provided in Appendix D.
Evaluation Protocol and Metrics. We use 100 demonstrations per task for post-training and evalu-
ate on the 8 real-world tasks in Table 2, 4 on each platform, with 3 × 16 rollouts per task (3 training
seeds, 16 evaluation rollouts per seed) under randomized initial object poses. Task definitions, eval-
uation settings, and per-task scoring rubrics are provided in Appendix E.
Quantitative and Qualitative Analysis. As shown in Table 2, AW-0 achieves the highest average
rubric score across both embodiments, outperforming the strongest baseline by 25.1 points. Two ob-
servations emerge. Language following and semantic reasoning: AW-0 outperforms the baselines
strongly on Arrange Fruits and Flip Scoreboard, which require instruction-specific object selec-
tion and counting, respectively. The VLA baselines, particularly π0.5, also show relatively strong
semantic understanding, while the WAM baselines are less reliable on these properties. These re-
sults suggest that code-based planning strengthens the language-following and semantic reasoning
of world action models. Robust skill execution: On contact-rich and dexterous tasks, DreamZero
outperforms π0.5 on Replace Lightbulb and Deal Poker, where predicting future states provides sta-
ble physical-dynamics features for action prediction. AW-0 further outperforms these baselines by
combining guidance from generated skill programs with predictive representations of physical dy-
namics, aligning skill-level planning with continuous control. See Appendix G for further analysis.
Hybrid Execution in the Real World. We further evaluate hybrid execution on Fold and Stack
Towels with the YAM platform based on Algorithm I, comparing it against action-chunk execution
under the same post-trained model and evaluation conditions. Under the same task rubric, hybrid
execution achieves 90.6%, compared with 84.4% for action-chunk execution, while the direct ex-
ecution steps of code further enhance the model’s reasoning capabilities in distinguishing stacking
order and action stability. Further visualizations are provided in Appendix G.3.

Q1: How should the code expert be integrated into a WAM? We first compare three blockwise
causal attention orders during joint denoising: V →A (w/o code), V →C →A, and C →V →A
(Figure 5). The two variants use the same pretraining data, training budget, and optimization settings
as AW-0. Adding code through V →C →A improves performance by grounding the predicted
dynamics to action, but restricts its role to reasoning over video predictions without guiding or
correcting them. With C →V →A, both video and action generation attend to code, allowing
semantic task plans to shape future prediction throughout denoising. The performance gain of this
ordering supports introducing semantic reasoning directly into video generation, which improves
language following and provides more reliable guidance for stable action generation.

Q2: What makes code an effective planning representation? To assess the planning content
produced by our annotation pipeline, we compare (1) full annotated programs, (2) code without
comments, (3) code without skills, and (4) natural-language subgoals in Figure 7. Full programs
outperform comment-free code on all 8 shared tasks, suggesting that explanatory language helps
connect program structure with task intent. Removing skill calls also reduces performance on all 8
evaluated tasks, especially on skill-required tasks such as Deal Poker (58.3% vs. 42.0%). Since this
variant still uses structured code, the drop supports the value of reusable skill abstractions beyond
primitive-level API composition. Full programs also beat language-only subgoals on 7 of 8 shared
tasks, showing that structured semantic guidance can provide more action-centric representation as
condition. Together, these comparisons support combining explanatory language, reusable skills,
and explicit program structure to provide effective planning guidance.
Q3: How does joint denoising affect performance and efficiency? As shown in Table 4, joint
denoising outperforms AR on 7 of 8 tasks. For AR models trained with teacher forcing, the mis-
match between ground-truth training prefixes and generated inference prefixes can cause errors to
accumulate during inference and affect downstream video prediction. Joint denoising reduces token-
by-token serial dependence by reconstructing code alongside video and actions, providing semantic
guidance throughout generation. We measure end-to-end inference latency on an NVIDIA RTX
5090, with settings detailed in Appendix A. Joint denoising takes 0.23 s versus 0.55 s for AR, a
2.39× speedup (Figure 6). Compared with the AW-0 w/o code (0.19 s), it adds 0.04 s (21.1%) while
improving performance on all 8 shared tasks (Figure 5).

RELATED WORK
World Action Models (WAMs).
World models predict future observations and have recently
emerged as a powerful paradigm for robot manipulation, serving as learned simulators and data
generators for policy learning (NVIDIA, 2025a;b; Gao et al., 2026; Yang et al., 2024; Jang et al.,
2025). Building on this progress, World Action Models (WAMs) unify future prediction and action
generation, through joint video-action diffusion (Ye et al., 2026; Zhu et al., 2025), expert-based ar-
chitectures (Bi et al., 2025; Cai et al., 2026), or direct adaptation of pretrained video models into
policies (Kim et al., 2026). Recent WAMs further couple autoregressive sub-task prediction with
future-state modeling and action synthesis (Yang et al., 2026) or dynamically update subtask in-
structions to condition video and action generation (Tang et al., 2026). However, existing WAMs
lack structured semantic guidance and explicit skill invocation, limiting their ability to perform com-
plex semantic planning and structure predicted dynamics into actionable behavioral abstractions.
Agentic Robotics. Early work composed perception and control APIs into executable closed-loop
behaviors without policy training (Ahn et al., 2022; Liang et al., 2023; Singh et al., 2023). Later
systems generate full Python programs over perception APIs (Huang et al., 2023; Mu et al., 2024;
Goldberg et al., 2025), and executable code has proven a stronger action space for LLM agents than
text (Wang et al., 2024). With the rise of coding agents, program synthesis has become explic-
itly agentic, with recent systems iteratively writing, executing, and repairing control programs (Lu
et al., 2026; Fu et al., 2026). Frontier models now also act as controllers themselves, reasoning over
instructions and feedback and driving robots directly through native tool calls and learned primi-
tives (Shi et al., 2025; Li et al., 2026; Gemini Robotics Team, 2025a;b). In all of these systems, the
9

agent controls the robot from outside the policy and is bounded by the primitives it can call. We
instead bring code inside an end-to-end model as a high-level planning interface and further explore
how the generated code can be executed to complement the model’s own actions at test time.
5
CONCLUSION
We present AW-0, an agentic world action model that integrates code-based skill planning with pre-
dictive dynamics and continuous control. Through joint denoising, the code expert provides struc-
tured semantic guidance for video and action generation. An automated annotation pipeline enables
learning this planning interface from large-scale robot and human demonstrations. Experiments on
RoboTwin 2.0 and real-world manipulation with YAM and dexterous hands demonstrate improve-
ments in language following, semantic reasoning, and skill execution, with hybrid execution further
enhancing robustness. These results establish a unified foundation for future work on skill reuse and
iterative interaction between programmatic planning, world prediction, and execution, providing a
potential agentic system foundation that continually interacts with and learns from environments.

A
MODEL AND TRAINING DETAILS
We implement the AW-0 architecture using three modality-specific experts coupled by masked joint
attention. All experts have 28 transformer layers and project their queries, keys, and values into a
common 2,048-dimensional attention space. The code expert receives current visual observations
and language instructions, the video expert attends to the code stream, and the action expert attends
to both. Tables 5 and 6 summarize the architecture and the pretraining configuration.
State and Action Representation. Both YAM robot data and egocentric human data are mapped
into a shared 64-dimensional state–action space. Each side contains a 9-dimensional end-effector
pose (3D of x, y, z position and a 6D rotation representation), 22 dexterous-hand joint angles, and
one parallel gripper width, giving 2 × (9 + 22 + 1) = 64 dimensions. States are all absolute; while
action chunks use end-effector pose deltas relative to the first frame of the chunk, with absolute
gripper targets for YAM and absolute hand-joint targets for human demonstrations/dexterous hand.
Dimensions unused by an embodiment—the hand-joint blocks for YAM and the gripper dimensions
for human demonstrations—are set to zero and left unnormalized. All remaining dimensions are
normalized using per-dimension 1st and 99th percentiles.
Initialization and Trainable Components. We initialize the video DiT from Cosmos-Predict2.5-
2B (NVIDIA, 2025b) and the action DiT from scratch before joint pretraining. The code expert
initializes its token embeddings, layer normalizations, FFNs, and vocabulary head from SDAR-
1.7B (Cheng et al., 2025) and freezes them, while training its MoT attention projections and mod-
ulation parameters.
The Qwen3-VL (Bai et al., 2025) vision tower is frozen, with a trainable
merger mapping visual features to code embeddings. We replace the original VAE with a frozen
Wan2.2 (Wan et al., 2025) VAE with 48 latent channels and reinitialize the video DiT’s input and
output projections. The video DiT uses 1 × 2 × 2 latent patches and multi-view 3D RoPE. Video
and action experts use precomputed Cosmos-Reason1 language embeddings. Downstream adapta-
tion transfers shape-compatible parameters from joint pretraining and reinitializes action and state
projections when embodiment dimensions change.

Joint Training and Decoding. Video noise resampling follows Section 2.2. The pretrained variable
is upre = 0.999b, where b ∼Beta(7, 1); training samples are drawn from q = 0.5ppre +0.5U(0, 1).

uniform-reference weight. Action noise levels and code-mask ratios are sampled independently
of the video variable. At least one program token is masked in every nonempty training target.

for 15% of training batches, retaining the visual prefix. The default decoder progressively commits
high-confidence code predictions across the full joint trajectory. Early completion is controlled by
ρ < 1, a separate decoding-time choice that does not change the training mask distribution. Latency

decoding, and action postprocessing.

both YAM and Tianji–Sharpa, we fine-tune AW-0 for 20 epochs using 100 demonstrations per task.

with a per-GPU batch size of 6 and one accumulation step, giving an effective batch size of 96, a
learning rate of 2 × 10−4, weight decay of 10−2, and a budget of 100,000 optimizer steps. These

BASELINE IMPLEMENTATION DETAILS
In Sections 3.1 and 3.2, we compare AW-0 with four baselines: π0.5, DreamZero, EgoScale, and
WLA. Here, we describe how each is reproduced and adapted. On RoboTwin 2.0, we train a single
multi-task policy per baseline on 2,500 demo clean demonstrations (50 tasks × 50 demonstra-
tions). For each of the 8 real-world tasks, we train a separate policy per baseline using task-specific
demonstrations sampled at 30 Hz. Every baseline receives a language instruction, the robot state,
and three RGB views (one head and two wrist cameras). All baselines follow the same evaluation
protocol as AW-0. All real-world rollouts are scored using the task-specific rubrics in Appendix E.
π0.5 (Black et al., 2025) is a vision-language-action model that combines a pretrained vision-
language backbone with a flow-matching action expert. We follow the official OpenPI implemen-
tation2 and initialize all policies from the released π0.5 pretrained checkpoint. For each real-world
task, we fine-tune a separate policy for 50 epochs on the task-specific demonstrations. We use
14-dimensional joint-space actions on RoboTwin and YAM, and 62-dimensional actions on Tianji–
Sharpa consisting of a 9-dimensional end-effector pose and 22 hand joints per side. Arm actions
are relative to the current state, while gripper and hand actions are absolute targets. We reinitialize
the action input and output projections to accommodate these dimensions and fine-tune all model
parameters. Following the official implementation, we use an action horizon of 50 for RoboTwin
and 32 for the real robots, together with quantile normalization and standard image augmentation.
All models are trained with AdamW on eight H100 GPUs using FSDP and a global batch size of
256. We use a peak learning rate of 5 × 10−5 with cosine decay to 5 × 10−6 and 2,000 warmup
steps.
DreamZero (Ye et al., 2026) is a world-action model that jointly generates future video and actions
using a pretrained video diffusion backbone. We follow the official implementation3 and initialize
from the DreamZero-AgiBot checkpoint. We reproduce DreamZero on RoboTwin and all 8 real-
world tasks, training a separate policy for 10 epochs on each real-world task. We fully fine-tune the
diffusion transformer and state/action modules, while keeping the text encoder, image encoder, and
video VAE frozen. Following the original design, the three camera views are tiled into one frame,
and each training sample contains up to four action chunks of 24 steps. Actions are predicted relative

state and action projections are adapted to the target embodiment, and the video and action losses

WLA (Yang et al., 2026) combines a vision-language backbone, a world expert, and an action

the end of the chunk, and its flow-matching loss is weighted by 0.1 relative to the action loss. All

peak learning rate of 5 × 10−5 with cosine decay to 5 × 10−6 and 1,000 warmup steps.

REAL-WORLD EXPERIMENTAL SETUP
We conduct data collection and policy evaluation on two robot embodiments: the YAM station with
parallel grippers and the Tianji–Sharpa station with dexterous hands. This section describes the
robot hardware, visual observations, and teleoperation interfaces used in our experiments. Figure 20
gives an overview of the two stations.
Robot Hardware and Control. The YAM station is a fixed-base bimanual system with two 6-DoF
arms, each equipped with a parallel gripper. The Tianji–Sharpa station consists of a Tianji humanoid
torso with two arms and two 22-DoF Sharpa dexterous hands. For AW-0, both embodiments use the
64-dimensional state–action representation described in Appendix A. The policy predicts relative
end-effector poses together with absolute gripper targets on YAM or absolute finger-joint targets on
Tianji–Sharpa.
Perception System. Both stations provide three RGB views: a head or overhead camera observes
the tabletop workspace, and a camera at each wrist provides a local view of the gripper or hand and
the manipulated objects. Each policy receives these images together with the task instruction and
robot state. For AW-0, images are resized to 224×320 pixels, and the state contains the end-effector
poses and the gripper positions or hand-joint angles. The same camera streams are provided to all
baselines, with method-specific preprocessing described in Appendix C.
Teleoperation and Data Collection. We collect YAM demonstrations using the standard YAM sta-
tion configuration, with two master arms and two puppet arms. The operator moves the master arms,
whose measured joint angles are sent as joint-position targets to the corresponding puppet arms. The
triggers on the teaching handles control the parallel gripper openings, yielding six arm-joint targets
and one gripper target per side. For Tianji–Sharpa, we use Manus gloves with PICO motion trackers
attached to the gloves, together with an Apple Vision Pro worn around the operator’s neck. The
tracked wrist positions and orientations define poses in SE(3), which are mapped to end-effector

and AW-0 w/o code targets the apple. These observations suggest that structured skill calls and
explicit object arguments provide a more specific planning condition for video prediction than a
natural-language subgoal alone. By connecting instruction semantics to concrete interactions, the
code stream helps align predicted dynamics with the intended task. Since the action expert also
conditions on predictive video representations, this alignment provides a pathway for improving
language following, complementing the execution results in our main experiments.

IMPACT OF CODE EXPERT ON SKILL ROBUSTNESS
We further examine whether code-based planning improves the prediction of physical dynamics and
skill robustness during precise manipulation. As shown in Figure 34, we compare the future frames
predicted by AW-0, Subgoal, and AW-0 w/o code for the right wrist camera on Deal Poker, focusing
on the final stage in which the right hand inserts a card into a slot. This interaction requires aligning
the held card with the narrow opening and guiding it into the slot, making the relative motion of the
hand, card, and receptacle critical to an accurate prediction. The three variants receive similar but
non-identical initial observations sampled at nearby time steps from the same episode.
The predicted futures reveal distinct differences in the insertion motion: AW-0 depicts the card
aligning with and entering the slot more accurately, whereas Subgoal and AW-0 w/o code produce
less coherent insertion sequences, with blur and distortions around the hand and manipulated objects.
These observations suggest that explicit skill calls and object arguments help the video expert better
predict how the hand and card should move relative to the receptacle. The implementation of the
code expert supports more accurate video generation, and therefore provides the action expert with
more reliable predictive guidance for precise manipulation.

HYBRID ACTIONS ALGORITHM
Algorithms 1 and 2 outline the workflow of the hybrid mode. From an observation o and instruction
ℓ, one forward pass of the policy π returns a direct action chunk a1:H over the replan horizon H and
a code slice c. Every slice executes in a shared namespace G containing the environment’s skill API,
reusable helper definitions, and its setup block (episode-start perception), which persists throughout
the episode. At each replanning point, ARBITRATE decides which of the two channels drives the
robot. The returned flag indicates whether code execution was attempted, not whether it succeeded.
If execution is attempted, the action chunk from the same policy invocation is discarded, even if an
exception occurs; the next iteration observes the current state and replans. Otherwise, the chunk is
played for H steps as in the default mode.
The original generated slice c is checked without repair. It is executed only if it passes the following
gates in order:
1. Stage Gate: its stage is not complete, is not below a stage already attempted, and has fewer
than R failed execution attempts;
2. Dependency Gate: every variable it reads is defined in G; and
3. Syntax, Whitelist, and Vacuity Gates: it compiles as generated, calls only whitelisted
functions, and contains an executable statement.

Perception and Control Primitives. During hybrid evaluation, generated code executes through
perception and control primitives implemented using Molmo for visual grounding (Deitke et al.,
2024), SAM 3 for segmentation (Carion et al., 2025), Contact-GraspNet for grasp generation (Sun-
dermeyer et al., 2021), and RoboTwin’s native motion-planning and gripper-control interfaces (Chen
et al., 2025). Neither the generated programs nor the underlying primitives access privileged simula-
tor information during evaluation. For demonstration collection, we preserve the same API interface
but use privileged object states and annotated grasps to improve collection efficiency.
Scope of Comparison. The default and hybrid configurations differ in both their training demon-
stration collection pipelines and execution modes to support their training requirements. Unlike the
default configuration, which uses demonstrations collected with RoboTwin’s native motion planner,
the hybrid configuration uses CaP-based data collection because it naturally pairs each demonstra-
tion with an aligned program executable in the RoboTwin simulator, supporting the code execution
component of hybrid actions. Therefore, our resulting comparison evaluates the two configuration
as a whole and does not isolate the effect of hybrid execution alone.
Code and Action Usage. Table 12 reports the fraction of simulation steps driven by each of the
two control channels during the hybrid evaluation in Table 1: execution of code produced by the
code expert and direct action chunks generated by the action expert. On successful episodes, code
drives 14.5% of steps in the clean setting and 35.0% in the random setting. The gap follows from
Table 1. In the clean setting, the action expert alone is already strong (80.8%), so there is little
for code to add. Admitting code in fact lowers success to 63.1%, which we attribute to the code
channel inheriting the failure modes of the low-level perception and control primitives it calls, and
the arbiter admits a code slice on validity alone, without predicting whether it will outperform the
action chunk it displaces. In the random setting, where direct action degrades to 20.6%, the code
channel carries a third of the physical time on the episodes that succeed and lifts success to 29.2%.
Executing the code expert’s generation thus complements the action expert especially where learned
actions are less reliable, here under visually out-of-distribution scenes. Pooled over all episodes,
code execution accounts for only 8.5% of steps in the clean setting and 5.6% in the random setting.
The pooled share is dominated by failed episodes, which run to the step cap and accumulate roughly
five times as many steps as successful ones (52.7k vs. 11.5k in clean, 55.5k vs. 8.4k in random),
almost all under direct action.
Qualitative Examples of Code–Action Interleaving. Figure 37 shows two qualitative examples of
how code execution and direct action generation interleave within an episode. The top progress bar
shows an episode of blocks ranking rgb, where the three blocks must be arranged in a row in
red, green, blue order. We observe that the three pick-and-place cycles are almost entirely carried
out by code execution, with direct action generation taking over around a stage transition. For tasks
of this kind that involve regularly shaped objects and well-structured motions, the integration is able

profile is within a fixed distance of the new slice, and loop templates are never reused. A miss triggers
the ordinary call, whose output is written back.
Coordinator protocol (Stage 1, skill discovery)
Role
A coding agent under a fixed written protocol that dispatches rounds, audits their output, and owns the
skill library. It never writes program code and never edits the annotator, prompts, API, or verification
code.
Round lifecycle
Dispatched, gated (all episodes annotated and scored), audited, done (admissions applied and logged).
The library is frozen from dispatch to done, and the next round starts only then.
Audit
Read the round summary, then per-task results, then the stored trace of each questionable slice (frames
seen, code written, verification outcome). Classify each as detector limit, annotator misread,
abstraction-level break, vocabulary gap, or segmentation artifact. Only vocabulary gaps feed skill
proposals.

Skill admission
A candidate is a straight-line composed function over the API, distilled from observed call sequences. It
is admitted if generic (episode-specific values lifted to parameters), recurrent across at least two tasks, at
the right level (a maneuver, not a task recipe), and not a duplicate. Its contact contract is derived by
expansion; on YAM the evidence slices must also reconcile against observed events. Admitted skills
enter the annotator prompt from the next round.

LIMITATIONS AND FUTURE WORK
Program Grounding and Skill Coverage. The code stream learns from automatically annotated
demonstrations and a curated skill library, making its planning quality dependent on annotation ac-
curacy and skill coverage. Generated programs can select an appropriate skill yet contain incorrect
arguments, as illustrated in Appendix F.1; syntactic validity therefore does not ensure correct exe-
cution. Future work could use execution feedback to improve program grounding and discover or
refine reusable skills beyond the initial library.
Predictive Robustness and Hybrid Execution. Structured planning improves WAM performance
but does not eliminate sensitivity to visual distribution shifts. Hybrid execution improves robustness
under RoboTwin randomization, yet reduces clean-setting performance (Appendix J.2). This trade-
off reflects both the reliability of the underlying primitives and the limitation of selecting code based
on validity without estimating its advantage over the action chunk. Learning to arbitrate using
execution reliability and expected task progress could better exploit the complementary strengths of
the two modes.
Toward Continual Agentic Learning. Our real-world hybrid evaluation is limited to YAM plat-
form due to the lack of code-as-policy systems for dexterous hand, and the current system does
not learn online from its own interactions. The unified design nevertheless offers a basis for cou-
pling program generation and world prediction with execution feedback and model updates. Future
work could explore iterative plan revision, skill-library expansion, and autonomous learning through
sustained environmental interaction, with broader evaluation across tasks and embodiments.
